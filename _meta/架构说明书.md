## 1. 概述

KOS_LLM-Wiki 是一个融合三类知识组织方法的个人知识管理系统：

| 方法 | 角色 | 层级 |
|------|------|------|
| **PARA** (Tiago Forte) | 操作上下文 | 文件夹级别 |
| **UDC** (Universal Decimal Classification) | 学科分类 | 笔记元数据 |
| **LLM-Wiki** | 知识领域 | 内容主题 |

### 核心目标

1. **可操作性** — 知识服务于行动，每个笔记都有明确的上下文归属
2. **可发现性** — 通过 UDC 分类 + 标签 + 双向链接三重机制确保内容可检索
3. **可演化性** — 系统随认知深化可重构，不依赖单一工具
4. **多语言性** — 同一知识体系支持简体中文、English、繁體中文三语言

## 3. PARA 文件夹结构

### 3.1 层级定义

| 层级 | 文件夹 | 生命周期 | 特征 |
|------|--------|----------|------|
| 0 | `00-Inbox/` | 捕获 | 待处理的闪念、素材、临时文件 |
| 1 | `01-Projects/` | 执行 | 有截止日期和具体产出的任务 |
| 2 | `02-Areas/` | 维护 | 无截止日期的长期关注领域 |
| 3 | `03-Resources/` | 参考 | 主题资料库，按学科组织 |
| 4 | `04-Archives/` | 休眠 | 以上三类的不活跃内容 |
| — | `06-Daily/` | 日记 | 每日笔记，时间轴视角 |
| — | `_meta/` | 元 | 系统自身的模板、脚本、附件 |

### 3.2 信息流

```
捕获 (Inbox) → 项目化 (Projects) → 完成
    ↓                                        ↓
归档 (Archives) ← 领域化 (Areas) ← 提炼 (Resources)
```

- Inbox 中的笔记经过处理后进入 Projects 或 Resources
- Projects 完成后，可交付物提炼到 Resources，项目笔记进入 Archives
- 高频关注的 Resources 可提升为 Areas

## 4. UDC 分类体系

### 4.1 本系统使用的 UDC 主类

| UDC 类号 | 类目 | 覆盖内容 |
|----------|------|----------|
| 001.8 | 知识组织与管理 | PARA 方法、KM 笔记、索引 |
| 004.8 | 人工智能 / LLM | 所有 LLM 相关笔记 |
| 025.4 | 分类法 | UDC 相关笔记 |
| 001.8:005 | 知识管理方法 | PARA 方法详述 |
| 001.8:004.8 | 知识组织 + AI | LLM 辅助 KM、RAG |

### 4.2 分类规则

1. **单类号** — 主题明确的笔记使用一个 UDC 类号
2. **组合类号** — 跨学科主题使用 `:` 连接（如 `001.8:004.8`）
3. **粒度控制** — 一般使用 4-7 位数字，必要时扩展
4. **一致性** — 同一概念在不同语言版本中使用相同 UDC 类号

### 4.3 在 Obsidian 中的实现

```yaml
---
udc: 001.8:004.8
tags: [resource, llm, kos]
---
```

查询方式：
- Obsidian 搜索：`udc:004.8`
- Dataview: `TABLE udc FROM "03-Resources" WHERE contains(udc, "004.8")`

## 5. 多语言架构

### 5.1 目录映射

```
简体中文版 (默认)     English 版         繁體中文版
─────────────────    ────────────        ────────────
/Home.md             en/Home.md          zh-tw/首頁.md
/_索引.md            en/_index.md        zh-tw/_index.md
/02-Areas/           en/02-Areas/        zh-tw/02-Areas/
/03-Resources/PARA/  en/03-Resources/PARA/  zh-tw/03-Resources/PARA/
/...                 en/...              zh-tw/...
/_meta/Templates/    en/_meta/Templates/ zh-tw/_meta/Templates/
```

### 5.2 同步规则

- 新增或修改笔记时，三个版本同时创建或更新
- 前置元数据中的 udc、tags 字段保持一致
- 链接交叉引用使用对应语言前缀（`en/`、`zh-tw/`）
- 各语言首页底部提供三语言切换链接

## 6. 数据模型

### 6.1 笔记级元数据 (frontmatter)

```yaml
---
created:      YYYY-MM-DD       # 创建日期，必填
updated:      YYYY-MM-DD       # 最后更新日期，必填
udc:          <类号>            # UDC 分类号，必填
tags:         [tag1, tag2]     # 标签数组，必填（至少包含一个分类标签）
aliases:      [别名1, 别名2]    # 别名，可选
status:       active | archived # 状态，仅 Projects 使用
priority:     <数字>            # 优先级，仅 Projects 使用
---
```

### 6.2 标签分类

| 类别 | 格式 | 示例 |
|------|------|------|
| 系统 | `#kos` | 系统核心笔记 |
| 领域 | `#area/*` | `#area/llm` |
| 资源 | `#resource/*` | `#resource/paras` |
| UDC | `#udc/*` | `#udc/004.8` |
| 模板 | `#template` | 模板笔记 |
| 每日 | `#daily` | 每日笔记 |

### 6.3 文件名规则

| 语言 | 格式 | 示例 |
|------|------|------|
| 简体中文 | 汉字 + 空格分隔 | `提示工程.md` |
| English | kebab-case | `prompt-engineering.md` |
| 繁體中文 | 漢字 + 空格分隔 | `提示工程.md` |

## 8. 模板系统

### 8.1 模板清单

| 模板 | 文件名 | 用途 |
|------|--------|------|
| 项目 | `project-template.md` / `项目模板.md` | 有截止日期的任务 |
| 领域 | `area-template.md` / `领域模板.md` | 长期关注的主题 |
| 资源 | `resource-template.md` / `资源模板.md` | 参考资料 |
| 概念 | `concept-template.md` / `概念模板.md` | 单个概念的原子笔记 |
| 每日 | `daily-note-template.md` / `每日笔记模板.md` | 日常记录 |

### 8.2 模板统一字段

所有模板均包含：
- `created` / `updated` — 时间戳
- `udc` — UDC 分类号（留空，使用时填写）
- `tags` — 标签数组（预填基础分类标签）

## 9. RAG 集成方案

### 9.1 架构

```
KOS_LLM-Wiki (Markdown)
       ↓
文本分块 (Chunking) → 按段落/标题分割
       ↓
Embedding → text-embedding-3-small / 其他模型
       ↓
向量数据库 → Chroma / FAISS / pgvector
       ↓
检索接口 → 用户查询 → 向量检索 → 相关片段 → LLM 回答
```

### 9.2 UDC 过滤

UDC 类号可作为 RAG 检索的元数据过滤器：

```
用户查询
  → 识别相关 UDC 类号（通过 LLM 分类或显式指定）
  → 限定检索范围到该类号下的笔记
  → 向量检索 + 关键字检索混合
  → 排序后注入 LLM 上下文
```

## 10. 维护流程

### 10.1 新增笔记流程

```
1. 确定笔记类型 → 选择合适的模板
2. 填写 UDC 类号和标签
3. 撰写内容，链接相关笔记
4. 同步创建三个语言版本
5. 更新三个索引文件的 PARA 表和 UDC 表
```

### 10.2 月度回顾

```
1. 检查 00-Inbox → 处理未归类的笔记
2. 检查 01-Projects → 更新进度或归档
3. 检查 02-Areas → 评估持续关注必要性
4. 检查 04-Archives → 必要时恢复
5. 更新索引文件（如有新增/删除笔记）
```

### 10.3 CI/CD（Git 为基础）

```
本地编辑 → git commit → 推送到远程
  → （可选）GitHub Action 触发：
    - Markdown lint 检查 frontmatter 完整性
    - 验证 UDC 类号是否在索引中
    - 检查跨语言版本一致性
    - 生成 RAG 向量索引
```

## 11. 技术栈

| 组件 | 选型 | 原因 |
|------|------|------|
| 编辑器 | Obsidian | 本地优先，Markdown 原生，图谱视图，插件生态 |
| 版本控制 | Git | 内容追溯，分支管理，多设备同步 |
| 格式 | Markdown + YAML frontmatter | 纯文本，工具无关，易于版本控制 |
| 分类法 | UDC | 学科全覆盖，语言中立，组合表达灵活 |
| 方法论 | PARA | 操作导向，与文件夹结构自然契合 |
| 查询 | Dataview（Obsidian 插件） | SQL 风格查询笔记元数据 |
| 模板 | Templater（Obsidian 插件） | 动态模板，插入日期等变量 |
| 向量检索 | Chroma / FAISS（可选） | RAG 知识问答 |
