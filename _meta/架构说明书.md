## 1. 概述

KOS_LLM-Wiki 是一个融合三类知识组织方法的个人知识管理系统，并在此基础上集成了 AI Agent（Codex）操作日志系统。

| 方法 | 角色 | 层级 |
|------|------|------|
| **PARA** (Tiago Forte) | 操作上下文 | 文件夹级别 |
| **UDC** (Universal Decimal Classification) | 学科分类 | 笔记元数据 |
| **LLM-Wiki** | 知识领域 | 内容主题 |
| **Codex-logs** | AI 审计追踪 | 操作日志 |

### 核心目标

1. **可操作性** — 知识服务于行动，每个笔记都有明确的上下文归属
2. **可发现性** — 通过 UDC 分类 + 标签 + 双向链接三重机制确保内容可检索
3. **可演化性** — 系统随认知深化可重构，不依赖单一工具
4. **多语言性** — 同一知识体系支持简体中文、English、繁體中文三语言
5. **可追溯性** — 所有 AI Agent 操作通过 `_logs/` 系统全程审计

### 设计来源

本系统受「LifeOS × LLM-Wiki 融合系统」（一只阿木木, 2026）启发，将原设计的 `AI-Log/` 日志体系本地化为 `_logs/` 目录，并将 Agent 从 Claude Code 替换为 Codex（OpenAI Coding Agent），适配 KOS_LLM-Wiki 的 PARA + UDC + 三语言架构。

| 025.4:001 | 分类理论 | UDC 分类索引 |
| 025.4:004 | 数字分类 | UDC 与数字知识管理 |

### 4.2 分类规则

1. **单类号** — 主题明确的笔记使用一个 UDC 类号
2. **组合类号** — 跨学科主题使用 `:` 连接（如 `001.8:004.8`）
3. **粒度控制** — 一般使用 4-7 位数字，必要时扩展
4. **一致性** — 同一概念在不同语言版本中使用相同 UDC 类号
5. **日志类号** — `_logs/` 下文件默认使用 `001.8:004.8`

### 4.3 在 Obsidian 中的实现

```yaml
---
udc: 001.8:004.8
tags: [resource, llm, kos]
---
```

查询方式：
- Obsidian 搜索：`udc:004.8`
- Dataview: `TABLE udc FROM "3 Resources" WHERE contains(udc, "004.8")`

## 5. 多语言架构

### 5.1 目录映射

```
简体中文版 (默认)     English 版              繁體中文版
─────────────────    ────────────             ────────────
/Home.md             en/Home.md               zh-tw/首頁.md
/_索引.md            en/_index.md             zh-tw/_index.md
/AGENTS.md           —                        —
/2 Areas/            en/2 Areas/              zh-tw/2 Areas/
/3 Resources/PARA/   en/3 Resources/PARA/     zh-tw/3 Resources/PARA/
/3 Resources/UDC/    en/3 Resources/UDC/      zh-tw/3 Resources/UDC/
/3 Resources/LLM-Wiki/ en/3 Resources/LLM-Wiki/ zh-tw/3 Resources/LLM-Wiki/
/_logs/              en/_logs/                zh-tw/_logs/
/_meta/              en/_meta/                zh-tw/_meta/
/_meta/Templates/    en/_meta/Templates/      zh-tw/_meta/Templates/
```

### 5.2 同步规则

- 新增或修改笔记时，三个版本同时创建或更新
- 前置元数据中的 `udc`、`tags` 字段保持一致
- 链接交叉引用使用对应语言前缀（`en/`、`zh-tw/`）
- 各语言首页底部提供三语言切换链接
- `_logs/` 内容本身以简体中文为主，但目录结构三语言镜像
- `AGENTS.md` 仅存在于根目录（供 Codex 读取），无需翻译

## 6. 数据模型

### 6.1 笔记级元数据 (frontmatter)

```yaml
---
created:      YYYY-MM-DD       # 创建日期，必填
updated:      YYYY-MM-DD       # 最后更新日期，必填
udc:          <类号>            # UDC 分类号，必填

priority:     <数字>            # 优先级，仅 Projects 使用
```

## 8. Codex-logs 日志系统

### 8.1 定位

`_logs/` 是 KOS_LLM-Wiki 的审计层，记录 Codex（AI Agent）的所有操作。其设计源自「LifeOS × LLM-Wiki 融合系统」的 `AI-Log/` 概念。

### 8.2 目录结构

```
_logs/
├── _index.md         # 日志系统需求说明书（含完整格式规范）
├── sessions/         # 会话日志（按年: YYYY/YYYY-MM-DD.md）
├── operations/       # 操作日志
│   ├── triage.md     #   分拣操作记录
│   ├── compile.md    #   编译操作记录
│   └── maintenance.md #  维护操作记录
├── tasks/            # 跨会话任务追踪（按年: YYYY/MM.md）
└── reports/          # 周期报告（weekly.md, monthly.md）
```

### 8.3 与内容层的关系

```
03-Resources/[topic]/wiki/log.md  ← 该子库的编译详情（技术日志）
_logs/operations/compile.md       ← 全局编译操作汇总（操作日志）
_logs/sessions/YYYY-MM-DD.md      ← 会话级操作摘要（审计日志）
```

子库日志记录「什么内容被编译」；全局日志记录「编译操作本身」；会话日志记录「本次会话做了什么」。

### 8.4 UDC 分类

| UDC | 类目 | 对应日志类型 |
|-----|------|-------------|
| 001.8:004.8 | 知识组织与 AI 日志 | 系统总日志、会话日志 |
| 004.8:005.1 | AI 操作审计 | 操作日志（triage/compile） |
| 004.8:681.5 | AI 系统维护 | 维护日志、任务追踪 |
| 001.8:311 | 知识管理统计 | 报告、统计分析 |

## 9. AI Agent 集成（Codex）

### 9.1 定位

Codex 是本系统的 AI Agent，负责自动化维护操作：分拣 Inbox、编译 Wiki、维护索引、记录日志。

### 9.2 操作流程

| 操作 | 触发 | 写入 | 日志记录 |
|------|------|------|----------|
| 分拣 Inbox | 用户请求 /triage | 目标目录 + _processed/ | `operations/triage.md` |
| Wiki 编译 | 新资料入库后 | 3 Resources/[topic]/wiki/ | `operations/compile.md` |
| 文件编辑 | 用户指令 | 目标文件 | 会话日志 |
| 系统维护 | 用户请求 /lint | — | `operations/maintenance.md` |
| 会话结束 | 自动 | — | `sessions/YYYY-MM-DD.md` |

### 9.3 宪法性文件

系统通过 `AGENTS.md` 定义 Codex 的行为规范（位于根目录），包括：
- 目录结构定义
- 新增笔记规范（frontmatter、UDC、标签、多语言同步）
- 索引更新要求
- 日志写入约束

### 9.4 与 LifeOS × LLM-Wiki 的差异

| 维度 | 原设计 | KOS_LLM-Wiki 适配 |
|------|--------|-------------------|
| Agent | Claude Code | Codex (OpenAI) |
| 宪法文件 | CLAUDE.md | AGENTS.md |
| 日志目录 | AI-Log/ | _logs/ |
| Inbox | 00-Inbox/ → _processed/ | 0 Inbox/ → Clippings/ |
| Wiki 子库 | 03-Resources/[topic]/{raw,wiki} | 3 Resources/[topic]/（无 raw/wiki 分层） |
| 分类法 | LifeOS 标签 | UDC + 标签双维度 |
| 语言 | 单语言 | 三语言镜像 |

## 11. RAG 集成方案

### 11.1 架构

```
KOS_LLM-Wiki (Markdown)
       ↓
文本分块 (Chunking) → 按段落/标题分割
       ↓
Embedding → text-embedding-3-small / 其他模型
       ↓
向量数据库 → Chroma / FAISS / pgvector
       ↓
检索接口 → 用户查询 → 向量检索 → 相关片段 → LLM 回答
```

### 11.2 UDC 过滤

UDC 类号可作为 RAG 检索的元数据过滤器：

```
用户查询
  → 识别相关 UDC 类号（通过 LLM 分类或显式指定）
  → 限定检索范围到该类号下的笔记
  → 向量检索 + 关键字检索混合
  → 排序后注入 LLM 上下文
```

## 12. 维护流程

### 12.1 新增笔记流程

```
1. 确定笔记类型 → 选择合适的模板
2. 填写 UDC 类号和标签
3. 撰写内容，链接相关笔记
4. 同步创建三个语言版本
5. 更新三个索引文件的 PARA 表和 UDC 表
6. 如由 Codex 操作，记录到 _logs/operations/
```

### 12.2 月度回顾

```
1. 检查 0 Inbox → 处理未归类的笔记
2. 检查 1 Projects → 更新进度或归档
3. 检查 2 Areas → 评估持续关注必要性
4. 检查 4 Archives → 必要时恢复
5. 检查 _logs/ → 回顾 Agent 操作记录，评估系统健康度
6. 更新索引文件（如有新增/删除笔记）
```

### 12.3 Git 版本控制

```
本地编辑 → git commit → 推送到远程
  → （可选）GitHub Action 触发：
    - Markdown lint 检查 frontmatter 完整性
    - 验证 UDC 类号是否在索引中
    - 检查跨语言版本一致性
    - 生成 RAG 向量索引
```

## 13. 技术栈

| 组件 | 选型 | 原因 |
|------|------|------|
| 编辑器 | Obsidian | 本地优先，Markdown 原生，图谱视图，插件生态 |
| AI Agent | Codex (OpenAI) | 代码级 Agent，支持文件读写、搜索、多步骤工作流 |
| 版本控制 | Git | 内容追溯，分支管理，多设备同步 |
| 格式 | Markdown + YAML frontmatter | 纯文本，工具无关，易于版本控制 |
| 分类法 | UDC | 学科全覆盖，语言中立，组合表达灵活 |
| 方法论 | PARA | 操作导向，与文件夹结构自然契合 |
| 查询 | Dataview（Obsidian 插件） | SQL 风格查询笔记元数据 |
| 模板 | Templater（Obsidian 插件） | 动态模板，插入日期等变量 |
| 向量检索 | Chroma / FAISS（可选） | RAG 知识问答 |
