# ADR-002: 日志系统设计

> **Architecture Decision Record**

| 字段 | 值 |
|------|-----|
| 编号 | ADR-002 |
| 状态 | Accepted |
| 日期 | 2026-06-07 |
| 作者 | Codex |
| 关联 | ADR-001 |

---

## 上下文

KOS_LLM-Wiki 在早期同时存在 `05-Logs/` 和 `_logs/` 两个日志目录，前者源自 PARA 分类的编号体系，后者源自 LifeOS 融合系统的 `_logs/` 惯例。

- **问题陈述**：两个日志目录并行导致操作记录分散；日志格式缺乏统一规范；会话日志、操作日志、周期笔记三者的边界模糊。
- **约束条件**：日志必须是追加式（append-only），不可修改历史记录；日志须支持三语言环境但不要求全部翻译；Codex Agent 的所有操作均须有审计追溯。
- **可选方案**：
  1. 沿用 `05-Logs/` 编号体系，日志作为 PARA 的一部分
  2. 统一使用 `_logs/` 下划线前缀，与 `_meta/` 组成系统目录家族
  3. 将日志分散到各 PARA 目录下（如 `1 Projects/xxx/log.md`）

## 决策

**选择方案：** 方案二 — 统一使用 `_logs/` 下划线前缀。

**理由：**
1. `_logs/` 与 `_meta/` 风格一致，明确标识为系统基础设施而非用户内容
2. 下划线前缀在文件排序中置顶，便于快速定位
3. 日志是元操作（meta-operation），不应与内容混在同一分类体系中
4. 支持追加式审计日志的独立存放，不受 PARA 重构影响

## 后果

### 正面
- 单一日志根目录，结构清晰
- 操作日志（triage.md / compile.md / maintenance.md）集中管理
- 会话日志（sessions/）与操作日志分离，职责明确

### 负面
- 日志目录独立于 PARA 体系，不参与索引
- 历史 `05-Logs/` 中的旧日志需要迁移

### 缓解措施
- `_logs/` 目录结构如下：
  ```
  _logs/
  ├── operations/       # 操作日志（追加式）
  │   ├── maintenance.md  # AGENTS.md 维护/项目操作
  │   ├── triage.md       # KOS-Triage 分拣记录
  │   └── compile.md      # KOS-Wiki-Compile 编译记录
  └── sessions/          # 会话日志（sessions/ 已预留）
  ```
- 每条日志记录采用统一的时间戳前缀（`YYYY-MM-DDTHH:MM`）
- `05-Logs/` 已迁移并清理，无需兼容层
