# ADR-003: 多语言同步策略

> **Architecture Decision Record**

| 字段 | 值 |
|------|-----|
| 编号 | ADR-003 |
| 状态 | Accepted |
| 日期 | 2026-06-07 |
| 作者 | Codex |
| 关联 | ADR-001 |

## 上下文

KOS_LLM-Wiki 支持三种语言：简体中文（`/`）、English（`en/`）、繁體中文（`zh-tw/`）。在系统演进过程中，三语言版本的同步范围、频率和自动化程度需要明确界定。

- **问题陈述**：哪些文件必须强制三语言同步？哪些可以单语言？同步机制是手工镜像还是自动化？如何处理三语言之间的内容差异？
- **约束条件**：不允许使用机器翻译（保持人工翻译质量）；核心导航文件（Home.md、索引）必须三语齐全；日志文件单语言（简体中文）以降低维护成本；Codex Agent 操作时需同时维护三语副本。
- **可选方案**：
  1. **全量同步** — 每个文件都创建三语言版本，包括日志
  2. **分层同步** — 核心内容强制同步，基础设施单语言
  3. **按需同步** — 不设硬性规则，由维护者自行决定

## 决策

**选择方案：** 方案二 — 分层同步。

**理由：**
1. 核心内容（Home.md、索引、架构说明书、ADR、模板）必须三语齐全，这是知识库的入口和文档骨架
2. 日志文件（maintenance.md, triage.md, compile.md）单语言（简体中文），降低维护负担
3. 内容笔记（3 Resources/、2 Areas/、1 Projects/）按作者语言创建，不强制翻译
4. 分层清晰：层1 强制同步 / 层2 按需 / 层3 单语言

### 三语言分层模型

| 层级 | 范围 | 同步策略 | 示例 |
|------|------|----------|------|
| **L1 导航层** | Home.md, _索引.md, AGENTS.md | 强制三语同步 | 入口文件 |
| **L2 系统文档层** | 架构说明书, ADR, C4 模型 | 强制三语同步 | 设计文档 |
| **L3 模板层** | _meta/Templates/ | 强制三语同步 | 概念模板 |
| **L4 内容层** | 3 Resources/, 2 Areas/, 1 Projects/ | 按作者语言 | LLM 基础.md |
| **L5 日志层** | _logs/operations/ | 单语言（简体） | triage.md |
| **L6 测试层** | _test_fixtures/ | 单语言（简体） | 测试夹具 |

## 后果

### 正面
- L1-L3 的三语同步确保系统入口和设计文档对三种语言的使用者都可用
- L4 允许内容创作者使用母语，无需为翻译付费
- L5-L6 单语言降低 40% 以上的维护成本

### 负面
- L1-L3 的每次修改需要同步三个副本（人工执行）
- 三语言索引之间的链接可能不同步
- 新加入的维护者需要理解分层策略

### 缓解措施
- 同步流程写入 AGENTS.md 的「多语言同步」章节
- 索引更新时强制检查三语言镜像的一致性
- 使用 `_index.md` / `en/_index.md` / `zh-tw/_index.md` 三向对比来发现差异
