# ADR-001: 目录结构命名规范

## 上下文

KOS_LLM-Wiki 最初使用 `00-Inbox/`、`01-Projects/`、`02-Areas/`、`03-Resources/`、`04-Archives/`、`05-Logs/`、`06-Daily/` 的编号命名方式，并在根目录同时存在 `0 Inbox/` 目录。

- **问题陈述**：双重 Inbox 目录（`00-Inbox` 和 `0 Inbox`）导致混淆；前导零的编号系统与 LifeOS 融合系统的 `0 Inbox` 风格不一致；`05-Logs/` 与已有 `_logs/` 目录重复。
- **约束条件**：向后兼容 Obsidian 链接；保持 PARA 编号层级可识别；目录名在文件系统中须合法。
- **可选方案**：
  1. 保留前导零格式（`00-`），合并重复目录
  2. 统一移除前导零（`0 Inbox`、`1 Projects`），`_logs` 保持下划线前缀
  3. 完全改用英文命名（`inbox/`、`projects/`）

## 决策

**选择方案：** 方案二 — 统一移除前导零，`_logs` 用下划线前缀表示系统目录。

**理由：**
1. 与 LifeOS × LLM-Wiki 融合系统的 `0 Inbox` 风格一致，降低认知成本
2. `_logs` 的下划线前缀遵循 `_meta` 的惯例，明确标识为系统目录而非内容目录
3. 移除前导零后仍保留数字排序（0 → 4），PARA 层级可直观识别
4. 中文命名 + 英文命名混合格式（`1 Projects`）在 Obsidian 中显示友好

## 后果

### 正面
- 目录结构更简洁，无冗余
- `_logs/` 与 `_meta/` 风格统一
- 所有链接需同步更新（一次性成本）

### 负面
- 所有现有 wiki 链接需要批量更新
- 外部引用（如书签、URL）指向旧路径会失效

### 缓解措施
- 使用 PowerShell 脚本批量替换所有文件中的路径引用
- 在 AGENTS.md 中明确记录新旧路径映射关系
- 旧目录名在 git 历史中可追溯，无需额外兼容层
