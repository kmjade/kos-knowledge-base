# kos-project：项目管理引擎

> 一次流程完成"项目立项 + 编号分配 + 文件落盘 + 领域关联"

---

## 触发机制

- **主动触发**：用户输入"新建项目 / 启动项目 / 立项 / 创建项目"
- **路由触发**：从 `kos` 入口或周期回顾中识别到项目创建意图

## 流程锁定规则

- 用户在回答中提到的"目标/截止日期/领域"等词，默认视为项目信息输入
- 仅在以下情况允许切换：
  - 用户明确输入其他命令
  - 用户明确要求停止本次项目创建
- 流程完成标志：目录已创建 + 主页已写入 + 领域页已同步

---

## 主流程

### 阶段一：收集项目信息

最低必填：
1. 项目名称
2. 所属领域（从 `2 Areas/` 中选择：学习/工作/生活 等）
3. 生命周期阶段（新建项目默认 `1-proposal`，也可直接指定 `2-execution`）

建议补充：
- 项目目标
- 截止日期
- 优先级（P1/P2/P3）

### 阶段二：编号分配

1. 扫描 `1 Projects/` 下**所有生命周期子目录**（`1-proposal/`、`2-execution/`、`3-completion/`）
2. 提取匹配 `YY-NN` 格式的项目条目 —— **目录（`26-NN 名称/`）与单文件（`26-NN 名称.md`）都算**（**排除**阶段看板 `{阶段}.md` 本身）
3. 取 `YY-` 后最大序号，新编号 = 最大序号 + 1（两位数补零）

规则：
- 同年内跨阶段统一递增（不按子阶段独立编号）
- 跨年后从 `YY-01` 重新开始
- 禁止猜测编号，必须基于实际扫描结果
- 示例：若当前最大为 `26-NN` → 新编号 = `26-(NN+1)`

### 阶段三：创建目录与主页

```
目标目录:  1 Projects/{{阶段}}/{{编号}} {{项目名称}}/
目标文件:  1 Projects/{{阶段}}/{{编号}} {{项目名称}}/{{编号}} {{项目名称}}.md
```

其中 `{{阶段}}` 默认 `1-proposal`（新项目）或用户指定的 `2-execution`。

1. 创建项目目录（含阶段前缀）
2. 用 `_meta/system/templates/modes/para/项目模板.md` 生成 `{{编号}} {{项目名称}}.md`
3. 写入 frontmatter 字段（参照实际项目约定）：

   ```yaml
   created: {{date:YYYY-MM-DD}}
   updated: {{date:YYYY-MM-DD}}
   udc: <根据领域按 UDC 映射表建议>
   tags: [project]
   status: proposal      # 1-proposal 阶段
   # 或 status: active   # 2-execution 阶段
   ```

   > UDC 建议对照 AGENTS.md 中的 L2 目录启发式：`1 Projects/*` → `001.8:005`

4. 确保 Dataview 面板正确（项目文件 + 最近更新）

### 阶段四：同步关联

**A — Dashboard 项目总览**
```
文件: 1 Projects/1 Projects.md
```

在"在册项目"表格追加一行。**名称列用 wikilink**（与阶段看板、三语索引一致）；
表格内 `[[wikilink]]` 的 `|` 须转义为 `\|`（`AGENTS.md` §表格格式**硬性要求** —— 未转义会把表撑裂）：
```
| {{YY-NN}} | [[{{项目路径}}\|{{项目名称}}]] | {{阶段}} | {{状态}} | {{优先级}} |
```

示例：
```
| 26-NN | [[1 Projects/2-execution/26-NN {{名称}}/26-NN {{名称}}\|{{名称}}]] | 2-execution | active | P2 |
```

- 如 Dashboard 不存在 → **全库无 Dashboard 专用模板**。本 SKILL 旧版所引 `_meta/system/templates/Dashboard模板.md`
  **从未存在**（`git log --all` 无该路径任何记录；`find` 全库无同物），属**幻影引用**，2026-09-20 更正。
  按 `kos-init` Step 2 的既定约定「无模板则创建最小骨架」办理：新建 `1 Projects/1 Projects.md`，
  写入标题 + 项目总览表头（**列定义以现存 `1 Projects/1 Projects.md` 为准**），再追加本行。
- 避免重复插入

**B — 领域页**
```
路径: 2 Areas/{{领域名}}/{{领域名}}.md
```

在"关联项目"区块追加（使用 wikilink）：
```
- [[1 Projects/{{阶段}}/{{编号}} {{名称}}/{{编号}} {{名称}}.md|{{编号}} {{名称}}]]
```

- 多领域项目同时关联多个领域页
- 无匹配领域页 → 询问用户是否新建，用 `_meta/system/templates/modes/para/领域模板.md` 创建

**C — 阶段看板**
```
文件: 1 Projects/{{阶段}}/{{阶段}}.md      # 1-proposal.md / 2-execution.md / 3-completion.md
```

在"项目列表"表格追加一行。**格式与根 Dashboard 不同** —— 阶段看板只有 **3 列**（`编号 | 名称 | 状态`，无「阶段」「优先级」）：

```
| {{YY-NN}} | [[1 Projects/{{阶段}}/{{编号}} {{名称}}\|{{名称}}]] | {{状态}} |
```

- 名称列同样用 wikilink，`|` 同样须转义为 `\|`
- 该项目**离开本阶段**时（转阶段 / 归档），将该行改为删除线 + 去向说明，**保留痕迹不删行**：
  `| ~~{{YY-NN}}~~ | ~~{{名称}}~~ | → 2-execution |`
- ⚠️ **勿漏此项** —— 本库 `2-execution.md` 曾因长期只维护根 Dashboard 而漂移：3 行中 **2 行是断链**、
  **6 个在册项目未收录**（2026-09-20 回填）。漂移是**结构性的**，不是偶发。

**D — 三语索引静态项目表**

`AGENTS.md` 硬性要求「**新建笔记后必须更新索引**（三语言同步）」。三份索引各有一张**手工静态项目表**：

| 语言 | 文件 | 名称列 |
|:----:|:-----|:-------|
| CN | `_meta/index/links/Index/_index-zh-cn.md` | 中文名 |
| EN | `en/_meta/index/links/Index/_index-en.md` | **英文显示名**（路径仍指向 CN，依 AGENTS.md 跨语言规则 C） |
| TW | `zh-tw/_meta/index/links/Index/_index.md` | 繁體名 |

- 三处均按 **`| [[{{路径}}\|{{显示名}}]] | {{阶段}} | {{状态}} |`**（3 列）追加，**三者行数与顺序必须一致**
- ⚠️ 表内 Dataview 块查的是 `1 Projects` / `en/1-projects` / `zh-tw/1-專案`，**查不到 `4 Archives/` 项**
  ⇒ 静态表**不可省**，它是**含归档项目的全量名册**

### 阶段五：输出结果

固定格式：
```
✅ 项目创建完成

项目编号: {{YY-NN}}
项目路径: [[1 Projects/{{阶段}}/{{编号}} {{名称}}/{{编号}} {{名称}}.md]]

已创建:
  - 1 Projects/{{阶段}}/{{编号}} {{名称}}/
  - 1 Projects/{{阶段}}/{{编号}} {{名称}}/{{编号}} {{名称}}.md

已更新:
  - 1 Projects/1 Projects.md                  # 根 Dashboard（5 列）
  - 1 Projects/{{阶段}}/{{阶段}}.md            # 阶段看板（3 列）
  - 2 Areas/{{领域}}/{{领域}}.md               # 领域页
  - _meta/index/links/Index/_index-zh-cn.md   # 三语索引静态项目表（CN）
  - en/_meta/index/links/Index/_index-en.md   # 同（EN）
  - zh-tw/_meta/index/links/Index/_index.md   # 同（TW）

下一步建议:
  - 完善成功标准与行动计划
  - 添加相关笔记链接
  - 开始第一阶段工作
```

## 快速立项模式

触发：用户只想先开项目框架，细节稍后补。

最小交付：
1. 确认项目名称与所属领域
2. 确认生命周期阶段（默认 `1-proposal`）
3. 编号分配（基于扫描结果）
4. 创建目录 + 生成基础项目主页
5. 更新根 Dashboard（5 列，**名称列** wikilink）+ **阶段看板**（3 列）+ 领域页（**编号列** wikilink）+ **三语索引静态项目表**

---

## 重要提醒

- 禁止使用示例数据，编号与名称必须来自真实扫描与用户输入
- 路径操作前先确认目标目录存在，不存在则创建
- 生命周期阶段子目录（`1-proposal/`、`2-execution/`、`3-completion/`）始终作为项目目录的父级；`4-archived/` 已于 2026-09-20 移除（物理目录暂留，规范地位取消）
- 编号扫描须覆盖**两种形态**：目录 `26-NN 名称/` **与**单文件 `26-NN 名称.md`（本库两者并存；只认目录会**漏号 → 重号**）；仅排除阶段看板 `{阶段}.md` 本身
- 涉及多领域时多点关联，但项目主页路径唯一
- Dashboard 行与领域页行**都**用 wikilink，差异在**落在哪一列**：Dashboard 落在**名称列**（编号列为纯文本 `{{YY-NN}}`），领域页落在**编号列**（名称为纯文本）。两者表格内 `|` 均须转义为 `\|`
- 创建后务必输出可追溯结果（含可点击路径）
