# kos-archive：项目归档引擎

> 在"项目结束"与"知识沉淀"之间建立闭环

---

## 触发机制

- **主动触发**：用户输入"归档 / 结项 / 完成项目 / 项目收尾"
- **路由触发**：从 `kos` 入口识别到归档意图

## 流程锁定规则

- 用户在回答中提到的"复盘/总结/提炼"等词，默认视为归档流程输入
- 仅在用户明确输入其他命令或要求停止时中断

---

## 主流程

### 阶段一：确认项目

1. 扫描 `1 Projects/` 下所有项目目录
2. 列出可归档项目清单
3. 用户指定项目编号或名称

### 阶段二：完成度检查

1. 读取项目主页的 `🎯 目标` 区块
2. 检查完成状态
3. 未完成 → 分支决策：
   - 标记为"部分完成"
   - 标记为"已放弃"
   - 剩余任务转新项目或待办

### 阶段三：快速复盘

```
- 主要成果（用户原话优先）
- 最大收获
- 关键教训
- 可复用经验
```

支持快速（最小集）和完整两种模式。

### 阶段四：标记可提炼内容

选择去向：
- **现在处理** → 归档后建议进入 kos-compile
- **待处理** → 在归档报告中标记
- **跳过**

### 阶段五：更新项目主页

1. 更新 frontmatter：`status: completed`, `completed: YYYY-MM-DD`
2. 追加"归档"区块：完成情况、复盘摘要、可提炼内容

### 阶段六：目录迁移

```
源: 1 Projects/{{编号}} {{名称}}/
目标: 4 Archives/{{编号}} {{名称}}/
```

- 移动前确认目标目录不存在（防覆盖）
- 移动后验证目标路径存在

### 阶段七：同步关联

**A — 项目总览**
- 从 `1 Projects/📍 项目总览.md` 的"活跃项目"移至"已完成项目"
- 链接更新为新路径

**B — 领域页**
- 从"关联项目"区块移至"历史归档"区块
- 路径更新为 `4 Archives/{{编号}} {{名称}}/`

### 阶段八：输出报告

```
✅ 归档完成

项目: {{编号}} {{名称}}
状态: 已完成 / 部分完成 / 已放弃
归档位置: [[4 Archives/{{编号}} {{名称}}/📍 项目总览.md]]

已更新:
  - 项目主页（status + 归档区块）
  - 1 Projects/📍 项目总览.md
  - 2 Areas/{{领域}}/{{领域}}.md

待处理:
  - [可提炼内容 1] → 建议 kos-compile
  - [可提炼内容 2] → 建议 kos-compile
```

## 快速归档模式

最小交付：
1. 项目确认
2. 完成度结论
3. 项目主页 + frontmatter 更新
4. 目录移动
5. 领域页同步
6. 归档报告

---

## 重要提醒

- 归档是**移动**，不是删除
- 项目编号在整个生命周期中保持不变（创建→活跃→归档）
- 目录移动前先确认目标目录不存在
- 链接路径必须同步更新

## 检查清单

- [ ] 已确认归档项目
- [ ] 已完成完成度检查（含未完成分支决策）
- [ ] 已完成复盘或快速归档
- [ ] 已标记可提炼内容去向
- [ ] 已更新项目主页与 frontmatter
- [ ] 已完成目录迁移
- [ ] 已更新项目总览
- [ ] 已更新领域页
- [ ] 已输出归档报告
