# 隔离区架构（Quarantine Zone）闪念

> 在 Inbox 和 raw/ 之间插入结构化隔离层，解决来源可信度、内容污染、元数据残缺问题。

## 核心思路

隔离区不是新目录，而是 frontmatter 状态机：用 quarantine.status 标记文件处于哪个检疫阶段。

管道：收集 → 0 Inbox/ → Triage → [隔离区: inbound/scanning/cleared/rejected] → raw/ → Compile → wiki/

## 质量门禁四级

| 级别 | 检查项 | 通过条件 |
|:----:|--------|---------|
| L0 | 最小元数据 | source_type + captured_at 存在 |
| L1 | 完整性 | 长度 > 50 字 + frontmatter 闭合 |
| L2 | 去重 | 全文相似度 < 80% |
| L3 | 置信度 | 主题识别置信度 > 0.5 |

## 关键设计决策

用标签和 frontmatter 替代物理目录移动，Dataview 可筛选，Obsidian 不感知。

## 待定问题

- 移动端捕获的 L0 检查是否能自动化（iOS Shortcut 补齐最小元数据）
