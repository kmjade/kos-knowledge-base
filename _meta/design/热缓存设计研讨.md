## 一、什么是 hot.md？

**核心定义**：一个 ~500 字的纯文本快照，回答一个问题——"上次做到哪了？"

它位于 claude-obsidian 的 `wiki/hot.md`，是会话级上下文缓存，而非日志。关键特征：

- **覆写而非追加** — 每次完全重写，不保留历史
- **~500 字上限** — 缓存不是日志，追求的是下一会话快速恢复
- **跨会话载体** — Claude Code 每次会话独立，hot.md 是跨会话记忆的唯一通道
- **跨项目引用** — 其他项目可指向此 vault，先读 hot.md 获取最新上下文

---

## 二、claude-obsidian 四段式生命周期

| 阶段 | Hook | 行为 |
|------|------|------|
| SessionStart | `cat wiki/hot.md` | 会话启动时自动注入最近上下文 |
| PostCompact | 提示 AI 重读 | 上下文压缩后重新加载，保持连续性 |
| 运行中 | SKILL.md 约定 | 每次 ingest / significant query 后更新 |
| Stop | `git diff` 检测变更后提示更新 | 如果本会话有 wiki/ 变更，提示 AI 写 hot.md |

## 三、讨论点 1：文件位置

| 候选路径 | 理由 | 问题 |
|---------|------|------|
| `_meta/hot.md` | 语义准确——hot.md 是系统元数据 | 藏在 `_meta/` 里不易被发现 |
| `_hot.md`（根目录） | 显眼，人和 AI 都能快速看到 | 根目录已有一定噪音 |
| `_meta/ai-memory/hot.md` | 和全局状态同类 | ai-memory 偏持久，hot 是易失缓存，语义不搭 |

**倾向**：`_meta/hot.md`，与设计文档、ADR、模板同属系统元数据。

→ 待确认用户倾向

## 四、讨论点 2：跨平台兼容

| 平台 | 自动读取能力 | 实现策略 |
|------|------------|---------|
| **Claude Code** | ✅ hooks.json 可配置 SessionStart + PostCompact | hooks 自动注入 |
| **Codex CLI** | ❌ 无 hooks 机制 | AGENTS.md 协议约定 |
| **OpenCode** | ❌ 无 hooks 机制 | AGENTS.md 协议约定 |

**建议方案：双轨制**
- Claude Code 轨道：hooks.json → SessionStart 自动 `cat _meta/hot.md` + PostCompact 自动重读
- Codex / OpenCode 轨道：AGENTS.md 会话协议中明确写入"启动时读 _meta/hot.md"

同时，架构说明中待实现的 PostCompact 和 PostToolUse hooks 可与此一并创建 hooks.json。

→ 待确认：是否同时创建 hooks.json

## 五、讨论点 3：更新粒度

| 事件 | 建议 | 理由 |
|------|------|------|
| **KOS-Triage 完成** | ✅ 更新 | Inbox 状态改变 |
| **KOS-Compile 完成** | ✅ 更新 | 产生了新知识页面 |
| **KOS-Link 完成** | ⬜ 可选 | 除非发现重大问题 |
| **KOS-Daily / 回顾** | ✅ 更新 | 周期性总结 |
| **普通对话** | ❌ 否 | 无 vault 状态变更 |
| **编辑/创建笔记** | ⬜ 看是否"有知识价值" | 防过度更新 |
| **会话结束** | ✅ 必须 | 关闭前最终写入 |

**原则**：只记对 vault 知识状态有实质改变的操作。会话内建议仅更新 1-2 次，避免频繁覆写变成日志。

## 六、讨论点 4：与现有日志的关系

**三分定位**：

```
_hot.md                    _logs/operations/          ai-memory/全局状态.md
─────────                  ────────────────           ─────────────────────
给 AI 做短期缓存            给人审计                    给 AI 做持久参考
易失 + 每次覆写             全量 + 不可变                半持久 + 手动更新
叙事性摘要                  结构化时间线                 状态快照
回答"上次做到哪了？"         回答"本周发生了什么？"        回答"系统长期状态？"
```

- **互补而非替代**
- Stop 时三者同时写入，但写不同的内容
- hot.md 负责叙事结论和下一步建议，`_logs/` 保留结构化事件列表

---

## 七、讨论点 5：初始状态

**倾向：创建种子文件**

理由：
1. 约定即文档——种子文件定义了这个机制的契约格式
2. 避免空文件判断——读取逻辑不用做存在性和空文件双重判断
3. 给第一轮会话一个起点

种子内容结构：frontmatter + Last Updated / Key Recent Facts / Recent Changes / Active Threads / Session State 五段，最后一条备注"此文件由 AI Agent 覆写，非追加"。
