# kos-archive：项目归档引擎

> 在"项目结束"与"知识沉淀"之间建立闭环

---

## 触发机制

- **主动触发**：用户输入"归档 / 结项 / 完成项目 / 项目收尾"
- **路由触发**：从 `kos` 入口或周期回顾中识别到归档意图

## 流程锁定规则

- 用户在回答中提到的"复盘/总结/提炼"等词，默认视为归档流程输入
- 仅在用户明确输入其他命令或要求停止时中断

---

## 主流程

### 阶段一：确认项目

1. 扫描 `1 Projects/` 下所有项目目录
2. 列出可归档项目清单
3. 用户指定项目编号或名称

### 阶段二：完成度检查

1. 读取项目主页的目标区块
2. 检查完成状态
3. 未完成 → 分支决策：标记为部分完成/已放弃/任务转移

### 阶段三：快速复盘

- 主要成果（用户原话优先）
- 最大收获
- 关键教训
- 可复用经验

支持快速（最小集）和完整两种模式。

### 阶段四：标记可提炼内容

选择去向：现在处理 / 待处理 / 跳过

### 阶段五：更新项目主页

1. 更新 frontmatter：`status: completed`, `completed: YYYY-MM-DD`
2. 追加归档区块

### 阶段六：目录迁移

```
源: 1 Projects/{{编号}} {{名称}}/
目标: 4 Archives/{{编号}} {{名称}}/
```

### 阶段七：同步关联

- 项目总览：从活跃移至已完成
- 领域页：从关联项目移至历史归档

### 阶段八：输出报告

输出项目编号、状态、归档位置、已更新页面、待处理提炼项。

---

## 快速归档模式

最小交付：确认项目 → 完成度结论 → 主页更新 → 目录移动 → 领域同步 → 报告

---

## 重要提醒

- 归档是移动，不是删除
- 项目编号在整个生命周期中保持不变
- 目录移动前先确认目标目录不存在
- 链接路径必须同步更新

## 检查清单

- [ ] 已确认归档项目
- [ ] 已完成完成度检查
- [ ] 已完成复盘或快速归档
- [ ] 已标记可提炼内容去向
- [ ] 已更新项目主页与 frontmatter
- [ ] 已完成目录迁移
- [ ] 已更新项目总览和领域页
- [ ] 已输出归档报告
