# 軟體工程架構設計

> **領域：** 持續關注軟體工程的架構設計方法、模式與實踐。

## 概述

軟體工程架構設計（Software Engineering Architecture Design）涵蓋從需求到實現的全鏈路架構決策。本領域記錄架構方法論、設計模式、品質屬性、文件化實踐與工程治理原則。

## 核心架構模式

| 模式 | 描述 | 適用場景 |
|------|------|----------|
| **分層架構** | 按職責水平分層（表現層/業務層/持久層） | 企業應用、傳統 Web 系統 |
| **六邊形架構** | 透過埠與轉接器隔離核心業務邏輯 | DDD 專案、需高測試性的系統 |
| **微服務架構** | 獨立部署的服務集合，透過 API 通訊 | 大型團隊、高伸縮性需求 |
| **事件驅動架構** | 元件透過事件非同步通訊 | 即時系統、CQRS、EDA |
| **CQRS** | 命令與查詢職責分離 | 讀寫負載不均的系統 |
| **事件溯源** | 以事件序列作為系統狀態的真實來源 | 審計追蹤、複雜業務狀態 |

## 設計原則

- **SOLID** — 單一職責、開放封閉、里氏替換、介面隔離、依賴反轉
- **DRY** — 不要重複自己（Don't Repeat Yourself）
- **YAGNI** — 你不需要它（You Ain't Gonna Need It）
- **KISS** — 保持簡單（Keep It Simple, Stupid）
- **LoD** — 最少知識原則（Law of Demeter）
- **CoC** — 慣例優於配置（Convention over Configuration）

## 架構品質屬性

| 屬性 | 定義 | 關鍵策略 |
|------|------|----------|
| 可維護性 | 修改成本與風險控制 | 模組化、低耦合、高內聚、清晰合約 |
| 可伸縮性 | 應對負載增長的能力 | 水準擴展、無狀態設計、快取 |
| 可用性 | 系統持續提供服務的能力 | 冗餘、故障轉移、熔斷 |
| 安全性 | 防禦未授權存取與攻擊 | 縱深防禦、最小權限、加密 |
| 可測試性 | 驗證系統行為的能力 | 依賴注入、介面抽象、測試金字塔 |
| 可觀測性 | 了解執行時期狀態的能力 | 日誌、指標、追蹤（三大支柱） |

## 架構文件化

- **C4 模型** — Context / Container / Component / Code 四層視圖
- **ADR** — 架構決策記錄（Architecture Decision Record），記錄每個關鍵決策的上下文與權衡
- **4+1 視圖** — 邏輯視圖、程序視圖、開發視圖、實體視圖 + 場景
- **UML** — 統一建模語言（用例圖、類別圖、時序圖等）
