# ADR-001: 目錄結構命名規範

> **Architecture Decision Record**

| 欄位 | 值 |
|------|-----|
| 編號 | ADR-001 |
| 狀態 | Accepted |
| 日期 | 2026-06-06 |
| 作者 | Codex |

## 上下文

KOS_LLM-Wiki 最初使用 `00-Inbox/`、`01-Projects/`、`02-Areas/`、`03-Resources/`、`04-Archives/`、`05-Logs/`、`06-Daily/` 的編號命名方式，並在根目錄同時存在 `0 Inbox/` 目錄。

- **問題陳述**：雙重 Inbox 目錄（`00-Inbox` 和 `0 Inbox`）導致混淆；前導零的編號系統與 LifeOS 融合系統的 `0 Inbox` 風格不一致；`05-Logs/` 與已有 `_meta/system/logs/` 目錄重複。
- **約束條件**：向後相容 Obsidian 連結；保持 PARA 編號層級可識別；目錄名在檔案系統中須合法。
- **可選方案**：
  1. 保留前導零格式（`00-`），合併重複目錄
  2. 統一移除前導零（`0 Inbox`、`1 Projects`），`_logs` 保持底線前綴
  3. 完全改用英文命名（`inbox/`、`projects/`）

## 決策

**選擇方案：** 方案二 — 統一移除前導零，`_logs` 用底線前綴表示系統目錄。

**理由：**
1. 與 LifeOS × LLM-Wiki 融合系統的 `0 Inbox` 風格一致，降低認知成本
2. `_logs` 的底線前綴遵循 `_meta` 的慣例，明確標識為系統目錄而非內容目錄
3. 移除前導零後仍保留數字排序（0 → 4），PARA 層級可直觀識別
4. 中文命名 + 英文命名混合格式（`1 Projects`）在 Obsidian 中顯示友好

## 後果

### 正面
- 目錄結構更簡潔，無冗餘
- `_meta/system/logs/` 與 `_meta/` 風格統一
- 所有連結需同步更新（一次性成本）

### 負面
- 所有現有 wiki 連結需要批次更新
- 外部引用（如書籤、URL）指向舊路徑會失效

### 緩解措施
- 使用 PowerShell 指令碼批次取代所有檔案中的路徑引用
- 在 AGENTS.md 中明確記錄新舊路徑對映關係
- 舊目錄名在 git 歷史中可追溯，無需額外相容層
