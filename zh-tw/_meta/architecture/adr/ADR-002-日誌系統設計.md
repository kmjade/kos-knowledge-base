# ADR-002: 日誌系統設計

> **Architecture Decision Record**

| 欄位 | 值 |
|------|-----|
| 編號 | ADR-002 |
| 狀態 | Accepted |
| 日期 | 2026-06-07 |
| 作者 | Codex |
| 關聯 | ADR-001 |

---

## 上下文

KOS_LLM-Wiki 早期同時存在 `05-Logs/`（來自 PARA 編號體系）和 `_meta/system/logs/`（來自 LifeOS 慣例）兩個日誌目錄。

- **問題陳述**：雙日誌目錄導致操作記錄分散；日誌格式缺乏統一規範；會話日誌、操作日誌、週期筆記三者邊界模糊。
- **約束條件**：日誌必須是追加式（append-only）；支援三語言環境但不需要全部翻譯；Codex Agent 的所有操作須有審計追溯。
- **可選方案**：
  1. 沿用 `05-Logs/` 編號體系
  2. 統一使用 `_meta/system/logs/` 底線前綴
  3. 將日誌分散到各 PARA 目錄下

## 決策

**選擇方案：** 方案二 — 統一使用 `_meta/system/logs/` 底線前綴。

**理由：**
1. `_meta/system/logs/` 與 `_meta/` 風格一致，標示為系統基礎設施
2. 底線前綴在檔案排序中置頂
3. 日誌是元操作（meta-operation），不應與內容混在同一個分類體系
4. 支援追加式審計日誌的獨立存放

## 後果

### 正面
- 單一日誌根目錄，結構清晰
- 操作日誌集中管理
- 會話日誌與操作日誌分離

### 負面
- 日誌目錄獨立於 PARA 體系，不參與索引
- 歷史 `05-Logs/` 中的舊日誌需要遷移

### 緩解措施
- `_meta/system/logs/` 目錄結構：
  ```
  _meta/system/logs/
  ├── operations/
  │   ├── maintenance.md
  │   ├── triage.md
  │   └── compile.md
  └── sessions/
  ```
- 每條日誌記錄使用 `YYYY-MM-DDTHH:MM` 時間戳前綴
