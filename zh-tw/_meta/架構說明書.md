## 1. 概述

KOS_LLM-Wiki 是一個融合三類知識組織方法的個人知識管理系統：

| 方法 | 角色 | 層級 |
|------|------|------|
| **PARA** (Tiago Forte) | 操作上下文 | 資料夾層級 |
| **UDC** (Universal Decimal Classification) | 學科分類 | 筆記元資料 |
| **LLM-Wiki** | 知識領域 | 內容主題 |

### 核心目標

1. **可操作性** — 知識服務於行動，每則筆記有明確的上下文歸屬
2. **可發現性** — 透過 UDC 分類 + 標籤 + 雙向連結三重機制確保內容可檢索
3. **可演化性** — 系統隨認知深化可重構，不依賴單一工具
4. **多語言性** — 同一知識體系支援簡體中文、English、繁體中文三語言

## 3. PARA 資料夾結構

### 3.1 層級定義

| 層級 | 資料夾 | 生命週期 | 特徵 |
|------|--------|----------|------|
| 0 | `00-Inbox/` | 捕獲 | 待處理的閃念、素材、暫存檔 |
| 1 | `01-Projects/` | 執行 | 有截止日期和具體產出的任務 |
| 2 | `02-Areas/` | 維護 | 無截止日期的長期關注領域 |
| 3 | `03-Resources/` | 參考 | 主題資料庫，按學科組織 |
| 4 | `04-Archives/` | 休眠 | 以上三類的不活躍內容 |
| — | `06-Daily/` | 日記 | 每日筆記，時間軸視角 |
| — | `_meta/` | 元 | 系統自身的模板、腳本、附件 |

### 3.2 資訊流

```
捕獲 (Inbox) → 專案化 (Projects) → 完成
    ↓                                          ↓
歸檔 (Archives) ← 領域化 (Areas) ← 提煉 (Resources)
```

- Inbox 中的筆記經過處理後進入 Projects 或 Resources
- Projects 完成後，可交付物提煉到 Resources，專案筆記進入 Archives
- 高頻關注的 Resources 可提升為 Areas

## 4. UDC 分類體系

### 4.1 本系統使用的 UDC 主類

| UDC 類號 | 類目 | 覆蓋內容 |
|----------|------|----------|
| 001.8 | 知識組織與管理 | PARA 方法、KM 筆記、索引 |
| 004.8 | 人工智慧 / LLM | 所有 LLM 相關筆記 |
| 025.4 | 分類法 | UDC 相關筆記 |
| 001.8:005 | 知識管理方法 | PARA 方法詳述 |
| 001.8:004.8 | 知識組織 + AI | LLM 輔助 KM、RAG |

### 4.2 分類規則

1. **單類號** — 主題明確的筆記使用一個 UDC 類號
2. **組合類號** — 跨學科主題使用 `:` 連接（如 `001.8:004.8`）
3. **粒度控制** — 一般使用 4-7 位數字，必要時擴展
4. **一致性** — 同一概念在不同語言版本中使用相同 UDC 類號

### 4.3 在 Obsidian 中的實現

```yaml
---
udc: 001.8:004.8
tags: [resource, llm, kos]
---
```

查詢方式：
- Obsidian 搜尋：`udc:004.8`
- Dataview: `TABLE udc FROM "zh-tw/03-Resources" WHERE contains(udc, "004.8")`

## 5. 多語言架構

### 5.1 目錄映射

```
簡體中文版 (預設)     English 版         繁體中文版
─────────────────    ────────────        ────────────
/Home.md             en/Home.md          zh-tw/首頁.md
/_索引.md            en/_index.md        zh-tw/_index.md
/02-Areas/           en/02-Areas/        zh-tw/02-Areas/
/03-Resources/PARA/  en/03-Resources/PARA/  zh-tw/03-Resources/PARA/
/...                 en/...              zh-tw/...
/_meta/Templates/    en/_meta/Templates/ zh-tw/_meta/Templates/
```

### 5.2 同步規則

- 新增或修改筆記時，三個版本同時建立或更新
- 前置元資料中的 udc、tags 欄位保持一致
- 連結交叉引用使用對應語言前綴（`en/`、`zh-tw/`）
- 各語言首頁底部提供三語言切換連結

## 6. 資料模型

### 6.1 筆記級元資料 (frontmatter)

```yaml
---
created:      YYYY-MM-DD       # 建立日期，必填
updated:      YYYY-MM-DD       # 最後更新日期，必填
udc:          <類號>            # UDC 分類號，必填
tags:         [tag1, tag2]     # 標籤陣列，必填（至少包含一個分類標籤）
aliases:      [別名1, 別名2]    # 別名，可選
status:       active | archived # 狀態，僅 Projects 使用
priority:     <數字>            # 優先級，僅 Projects 使用
---
```

### 6.2 標籤分類

| 類別 | 格式 | 範例 |
|------|------|------|
| 系統 | `#kos` | 系統核心筆記 |
| 領域 | `#area/*` | `#area/llm` |
| 資源 | `#resource/*` | `#resource/paras` |
| UDC | `#udc/*` | `#udc/004.8` |
| 模板 | `#template` | 模板筆記 |
| 每日 | `#daily` | 每日筆記 |

### 6.3 檔案命名規則

| 語言 | 格式 | 範例 |
|------|------|------|
| 簡體中文 | 漢字 + 空格分隔 | `提示工程.md` |
| English | kebab-case | `prompt-engineering.md` |
| 繁體中文 | 漢字 + 空格分隔 | `提示工程.md` |

## 7. 導航系統

### 7.1 入口層級

```
Level 0: 首頁.md             — 系統入口，快速導航表
Level 1: _index.md           — 總索引（PARA + UDC 雙維度）
Level 2: 各資料夾 README     — 分類概覽（預留）

```

```
| [[連結到筆記\|顯示名稱]]            | 001.8:005    | #resource/paras        |
```

**UDC 維度表：**

```
| UDC 類號      | 類目           | 相關筆記                               |
|---------------|----------------|----------------------------------------|
| 001.8         | 知識組織與管理 | 首頁, _index, 知識管理, ...            |
```

## 8. 模板系統

### 8.1 模板清單

| 模板 | 檔案名稱 | 用途 |
|------|----------|------|
| 專案 | `project-template.md` / `項目模板.md` | 有截止日期的任務 |
| 領域 | `area-template.md` / `領域模板.md` | 長期關注的主題 |
| 資源 | `resource-template.md` / `資源模板.md` | 參考資料 |
| 概念 | `concept-template.md` / `概念模板.md` | 單一概念的原子筆記 |
| 每日 | `daily-note-template.md` / `每日筆記模板.md` | 日常記錄 |

### 8.2 模板統一欄位

所有模板均包含：
- `created` / `updated` — 時間戳
- `udc` — UDC 分類號（留空，使用時填寫）
- `tags` — 標籤陣列（預填基礎分類標籤）

## 9. RAG 整合方案

### 9.1 架構

```
KOS_LLM-Wiki (Markdown)
       ↓
文字分塊 (Chunking) → 按段落/標題分割
       ↓
Embedding → text-embedding-3-small / 其他模型
       ↓
向量資料庫 → Chroma / FAISS / pgvector
       ↓
檢索介面 → 使用者查詢 → 向量檢索 → 相關片段 → LLM 回答
```

### 9.2 UDC 過濾

UDC 類號可作為 RAG 檢索的元資料過濾器：

```
使用者查詢
  → 識別相關 UDC 類號（透過 LLM 分類或明確指定）
  → 限定檢索範圍到該類號下的筆記
  → 向量檢索 + 關鍵字檢索混合
  → 排序後注入 LLM 上下文
```

## 10. 維護流程

### 10.1 新增筆記流程

```
1. 確定筆記類型 → 選擇合適的模板
2. 填寫 UDC 類號和標籤
3. 撰寫內容，連結相關筆記
4. 同步建立三個語言版本
5. 更新三個索引檔案的 PARA 表和 UDC 表
```

### 10.2 月度回顧

```
1. 檢查 00-Inbox → 處理未歸類的筆記
2. 檢查 01-Projects → 更新進度或歸檔
3. 檢查 02-Areas → 評估持續關注必要性
4. 檢查 04-Archives → 必要時恢復
5. 更新索引檔案（如有新增/刪除筆記）
```

### 10.3 CI/CD（Git 為基礎）

```
本地編輯 → git commit → 推送到遠端
  → （可選）GitHub Action 觸發：
    - Markdown lint 檢查 frontmatter 完整性
    - 驗證 UDC 類號是否在索引中
    - 檢查跨語言版本一致性
    - 生成 RAG 向量索引
```

## 11. 技術棧

| 組件 | 選型 | 原因 |
|------|------|------|
| 編輯器 | Obsidian | 本地優先，Markdown 原生，圖譜檢視，外掛生態 |
| 版本控制 | Git | 內容追溯，分支管理，多裝置同步 |
| 格式 | Markdown + YAML frontmatter | 純文字，工具無關，易於版本控制 |
| 分類法 | UDC | 學科全覆蓋，語言中立，組合表達靈活 |
| 方法論 | PARA | 操作導向，與資料夾結構自然契合 |
| 查詢 | Dataview（Obsidian 外掛） | SQL 風格查詢筆記元資料 |
| 模板 | Templater（Obsidian 外掛） | 動態模板，插入日期等變數 |
| 向量檢索 | Chroma / FAISS（可選） | RAG 知識問答 |
