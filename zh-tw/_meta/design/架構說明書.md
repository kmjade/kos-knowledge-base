## 1. 概述

KOS_LLM-Wiki 是一個融合三類知識組織方法的個人知識管理系統，並在此基礎上整合了 AI Agent（Codex）操作日誌系統。

| 方法 | 角色 | 層級 |
|------|------|------|
| **PARA** (Tiago Forte) | 操作上下文 | 資料夾層級 |
| **UDC** (Universal Decimal Classification) | 學科分類 | 筆記元資料 |
| **LLM-Wiki** | 知識領域 | 內容主題 |
| **Codex-logs** | AI 審計追蹤 | 操作日誌 |

### 核心目標

1. **可操作性** — 知識服務於行動，每則筆記有明確的上下文歸屬
2. **可發現性** — 透過 UDC 分類 + 標籤 + 雙向連結三重機制確保內容可檢索
3. **可演化性** — 系統隨認知深化可重構，不依賴單一工具
4. **多語言性** — 同一知識體系支援簡體中文、English、繁體中文三語言
5. **可追溯性** — 所有 AI Agent 操作透過 `_logs/` 系統全程審計

### 設計來源

本系統受「LifeOS × LLM-Wiki 融合系統」（一隻阿木木, 2026）啟發，將原設計的 `AI-Log/` 日誌體系本地化為 `_logs/` 目錄，並將 Agent 從 Claude Code 替換為 Codex（OpenAI Coding Agent），適配 KOS_LLM-Wiki 的 PARA + UDC + 三語言架構。

### 4.2 分類規則

1. **單類號** — 主題明確的筆記使用一個 UDC 類號
2. **組合類號** — 跨學科主題使用 `:` 連接（如 `001.8:004.8`）
3. **粒度控制** — 一般使用 4-7 位數字，必要時擴展
4. **一致性** — 同一概念在不同語言版本中使用相同 UDC 類號
5. **日誌類號** — `_logs/` 下文件預設使用 `001.8:004.8`

## 5. 多語言架構

### 5.1 目錄映射

```
簡體中文版 (預設)     English 版              繁體中文版
─────────────────    ────────────             ────────────
/Home.md             en/Home.md               zh-tw/首頁.md
/_索引.md            en/_index.md             zh-tw/_index.md
/AGENTS.md           —                        —
/2 Areas/            en/2 Areas/              zh-tw/2 Areas/
/3 Resources/000-Knowledge/001-PARA/   en/3 Resources/000-Knowledge/001-PARA/     zh-tw/3 Resources/000-Knowledge/001-PARA/
/_logs/              en/_logs/                zh-tw/_logs/
/_meta/              en/_meta/                zh-tw/_meta/
/_meta/Templates/    en/_meta/Templates/      zh-tw/_meta/Templates/
```

### 5.2 同步規則

- 新增或修改筆記時，三個版本同時建立或更新
- 前置元資料中的 `udc`、`tags` 欄位保持一致
- 連結交叉引用使用對應語言前綴（`en/`、`zh-tw/`）
- 各語言首頁底部提供三語言切換連結
- `_logs/` 內容本身以簡體中文為主，但目錄結構三語言鏡像
- `AGENTS.md` 僅存在於根目錄（供 Codex 讀取），無需翻譯

## 6. 資料模型

### 6.1 筆記級元資料 (frontmatter)

```yaml
---
created:      YYYY-MM-DD       # 建立日期，必填
updated:      YYYY-MM-DD       # 最後更新日期，必填
udc:          <類號>            # UDC 分類號，必填
tags:         [tag1, tag2]     # 標籤陣列，必填（至少包含一個分類標籤）
aliases:      [別名1, 別名2]    # 別名，可選
status:       active | archived # 狀態，僅 Projects 使用
priority:     <數字>            # 優先級，僅 Projects 使用
---
```

### 6.2 標籤分類

| 類別 | 格式 | 範例 | 說明 |

| 資源 | `#resource/*` | `#resource/paras` | 3 Resources 下筆記 |

## 8. Codex-logs 日誌系統

### 8.1 定位

`_logs/` 是 KOS_LLM-Wiki 的審計層，記錄 Codex（AI Agent）的所有操作。其設計源自「LifeOS × LLM-Wiki 融合系統」的 `AI-Log/` 概念。

### 8.2 目錄結構

```
_logs/
├── _index.md         # 日誌系統需求說明書（含完整格式規範）
├── sessions/         # 會話日誌（按年: YYYY/YYYY-MM-DD.md）
├── operations/       # 操作日誌
│   ├── triage.md     #   分揀操作記錄
│   ├── compile.md    #   編譯操作記錄
│   └── maintenance.md #  維護操作記錄
├── tasks/            # 跨會話任務追蹤（按年: YYYY/MM.md）
└── reports/          # 週期報告（YYYY-WW.md, YYYY-MM.md）
```

### 8.3 與內容層的關係

```
3 Resources/[topic]/wiki/log.md  ← 該子庫的編譯詳情（技術日誌）
_logs/operations/compile.md      ← 全域編譯操作彙總（操作日誌）
_logs/sessions/YYYY-MM-DD.md     ← 會話級操作摘要（審計日誌）
```

子庫日誌記錄「什麼內容被編譯」；全域日誌記錄「編譯操作本身」；會話日誌記錄「本次會話做了什麼」。

## 9. AI Agent 整合（Codex）

### 9.1 定位

Codex 是本系統的 AI Agent，負責自動化維護操作：分揀 Inbox、編譯 Wiki、維護索引、記錄日誌。

### 9.2 操作流程

| 操作 | 觸發 | 寫入 | 日誌記錄 |
|------|------|------|----------|
| 分揀 Inbox | 使用者請求 /triage | 目標目錄 + _processed/ | `operations/triage.md` |
| Wiki 編譯 | 新資料入庫後 | 3 Resources/[topic]/wiki/ | `operations/compile.md` |
| 檔案編輯 | 使用者指令 | 目標檔案 | 會話日誌 |
| 系統維護 | 使用者請求 /lint | — | `operations/maintenance.md` |
| 會話結束 | 自動 | — | `sessions/YYYY-MM-DD.md` |

### 9.3 憲法性文件

系統透過 `AGENTS.md`（位於根目錄）定義 Codex 的行為規範，包括：
- 目錄結構定義
- 新增筆記規範（frontmatter、UDC、標籤、多語言同步）
- 索引更新要求
- 日誌寫入約束

### 9.4 與 LifeOS × LLM-Wiki 的差異

| 維度 | 原設計 | KOS_LLM-Wiki 適配 |
|------|--------|-------------------|
| Agent | Claude Code | Codex (OpenAI) |
| 憲法文件 | CLAUDE.md | AGENTS.md |
| 日誌目錄 | AI-Log/ | _logs/ |
| Inbox | 00-Inbox/ → _processed/ | 0 Inbox/ → Clippings/ |
| Wiki 子庫 | raw/ + wiki/ 雙層結構 | 單一主題目錄（無 raw/wiki 分層） |
| 分類法 | LifeOS 標籤 | UDC + 標籤雙維度 |
| 語言 | 單語言 | 三語言鏡像 |

## 10. 模板系統

### 10.1 模板清單

| 模板 | 檔案名稱 | 用途 |
|------|----------|------|
| 專案 | `project-template.md` / `項目模板.md` | 有截止日期的任務 |

## 12. 維護流程

### 12.1 新增筆記流程

```
1. 確定筆記類型 → 選擇合適的模板
2. 填寫 UDC 類號和標籤
3. 撰寫內容，連結相關筆記
4. 同步建立三個語言版本
5. 更新三個索引檔案的 PARA 表和 UDC 表
6. 如由 Codex 操作，記錄到 _logs/operations/
```

### 12.2 月度回顧

```
1. 檢查 0 Inbox → 處理未歸類的筆記
2. 檢查 1 Projects → 更新進度或歸檔
3. 檢查 2 Areas → 評估持續關注必要性
4. 檢查 4 Archives → 必要時恢復
5. 檢查 _logs/ → 回顧 Agent 操作記錄，評估系統健康度
6. 更新索引檔案（如有新增/刪除筆記）
```

## 13. 技術棧

| 組件 | 選型 | 原因 |
|------|------|------|
| 編輯器 | Obsidian | 本地優先，Markdown 原生，圖譜檢視，外掛生態 |
| AI Agent | Codex (OpenAI) | 程式碼級 Agent，支援檔案讀寫、搜尋、多步驟工作流 |
| 版本控制 | Git | 內容追溯，分支管理，多裝置同步 |
| 格式 | Markdown + YAML frontmatter | 純文字，工具無關，易於版本控制 |
| 分類法 | UDC | 學科全覆蓋，語言中立，組合表達靈活 |
| 方法論 | PARA | 操作導向，與資料夾結構自然契合 |
| 查詢 | Dataview（Obsidian 外掛） | SQL 風格查詢筆記元資料 |
| 模板 | Templater（Obsidian 外掛） | 動態模板，插入日期等變數 |
| 向量檢索 | Chroma / FAISS（可選） | RAG 知識問答 |
