# PARA 與知識管理

> **資源：** PARA 在個人知識管理（PKM）中的深入應用與實踐。

---

## 核心內容

### 信息流模型

PARA 本質是一個**信息過濾器**，從粗糙的搜集到精煉的知識：

```
採集 → 項目化 → 完成 → 領域化 → 固化認知 → 歸檔
```

1. **採集階段** — 閃念筆記、書籤、截圖 → 放入 `06-Daily` 或 `0 Inbox`
2. **項目化** — 判斷是否有明確的產出目標 → 創建項目
3. **執行階段** — 在項目文件夾中推進，產生具體成果
4. **領域化** — 項目完成後，將可復用的知識沉澱到領域
5. **歸檔** — 不再活躍的項目/領域移至 `4 Archives/`

### PARA 與 Zettelkasten

| 維度 | PARA | Zettelkasten |
|------|------|-------------|
| 焦點 | 行動與完成 | 連接與發現 |
| 結構 | 樹形文件夾 | 網狀連結 |
| 生命周期 | 從活躍到歸檔 | 永久積累 |
| 適用場景 | 項目管理 | 知識發現 |

兩者互補：PARA 管理"做什麼"，Zettelkasten 管理"知道什麼"。

### 結合 UDC

每條筆記標註 UDC 類號，使 PARA 的操作上下文與 UDC 的學科維度正交配合：

```

```


## 資訊流模型

PARA 本質是一個**資訊過濾器**，從粗糙的蒐集到精煉的知識：

```
採集 → 專案化 → 完成 → 領域化 → 固化認知 → 歸檔
```

1. **採集階段** — 閃念筆記、書籤、截圖 → 放入 `06-Daily` 或 `_meta/Inbox`
2. **專案化階段** — 將相關素材提煉為具體的專案產出
3. **完成階段** — 專案交付後，提煉可複用的知識
4. **領域化階段** — 將高頻複用的知識提升為領域標準
5. **歸檔階段** — 低價值/低頻率的知識進入歸檔

## 與 Zettelkasten 的區別

| 特性 | PARA | Zettelkasten |
|------|------|-------------|
| 組織方式 | 資料夾（樹狀）| 連結（網狀）|
| 原子性 | 筆記可大可小 | 原子化（一概念一筆記）|
| 導航 | 分類瀏覽 | 連結跳轉 |
| 適合場景 | 專案管理、GTD | 學術研究、寫作 |

> 本系統**融合兩者**：使用 PARA 的資料夾結構作為骨架，使用 Obsidian 的雙向連結實現 Zettelkasten 式的網狀連接。

## 與 GTD 的對比

- **GTD** (Getting Things Done) 側重任務管理 → 解決「如何做」
- **PARA** 側重知識組織 → 解決「知識放哪裡」
- 本系統以 PARA 為組織核心，專案筆記中嵌入 GTD 的 Next Action

## 實踐技巧

### 資料夾 vs 標籤 vs 連結
| 維度 | 用途 |
|------|------|
| 資料夾 | 粗粒度分類（PARA 四級結構）|
| 標籤 | 跨分類的維度和狀態（#area, #resource, #todo）|
| 連結 | 筆記之間的語意關聯 |
