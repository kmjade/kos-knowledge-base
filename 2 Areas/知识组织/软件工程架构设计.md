# 软件工程架构设计

> **领域：** 持续关注软件工程的架构设计方法、模式与实践。

## 概述

软件工程架构设计（Software Engineering Architecture Design）涵盖从需求到实现的全链路架构决策。本领域记录架构方法论、设计模式、质量属性、文档化实践与工程治理原则。

## 核心架构模式

| 模式 | 描述 | 适用场景 |
|------|------|----------|
| **分层架构** | 按职责水平分层（表现层/业务层/持久层） | 企业应用、传统 Web 系统 |
| **六边形架构** | 通过端口与适配器隔离核心业务逻辑 | DDD 项目、需高测试性的系统 |
| **微服务架构** | 独立部署的服务集合，通过 API 通信 | 大型团队、高伸缩性需求 |
| **事件驱动架构** | 组件通过事件异步通信 | 实时系统、CQRS、EDA |
| **CQRS** | 命令与查询职责分离 | 读写负载不均的系统 |
| **事件溯源** | 以事件序列作为系统状态的真实来源 | 审计追踪、复杂业务状态 |

## 设计原则

- **SOLID** — 单一职责、开放封闭、里氏替换、接口隔离、依赖反转
- **DRY** — 不要重复自己（Don't Repeat Yourself）
- **YAGNI** — 你不会需要它（You Ain't Gonna Need It）
- **KISS** — 保持简单（Keep It Simple, Stupid）
- **LoD** — 最少知识原则（Law of Demeter）
- **CoC** — 约定优于配置（Convention over Configuration）

## 架构质量属性

| 属性 | 定义 | 关键策略 |
|------|------|----------|
| 可维护性 | 修改成本与风险控制 | 模块化、低耦合、高内聚、清晰契约 |
| 可伸缩性 | 应对负载增长的能力 | 水平扩展、无状态设计、缓存 |
| 可用性 | 系统持续提供服务的能力 | 冗余、故障转移、熔断 |
| 安全性 | 防御未授权访问与攻击 | 纵深防御、最小权限、加密 |
| 可测试性 | 验证系统行为的能力 | 依赖注入、接口抽象、测试金字塔 |
| 可观测性 | 了解运行时状态的能力 | 日志、指标、追踪（三大支柱） |

## 架构文档化

- **C4 模型** — Context / Container / Component / Code 四层视图
- **ADR** — 架构决策记录（Architecture Decision Record），记录每个关键决策的上下文与权衡
- **4+1 视图** — 逻辑视图、进程视图、开发视图、物理视图 + 场景
- **UML** — 统一建模语言（用例图、类图、时序图等）
