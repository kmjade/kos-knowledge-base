# PARA & Knowledge Management

> **Resource:** Deep dive into PARA application in Personal Knowledge Management (PKM).

---

## Information Flow Model

PARA is essentially an **information filter**, from raw collection to refined knowledge:

```
Capture → Projectize → Complete → Area-ize → Solidify → Archive
```

1. **Capture** — Fleeting notes, bookmarks, screenshots → place in `06-Daily` or `_meta/Inbox`
2. **Projectize** — Refine related material into specific project deliverables
3. **Complete** — After delivery, extract reusable knowledge
4. **Area-ize** — Promote frequently-used knowledge into area standards
5. **Archive** — Low-value/low-frequency knowledge goes to archives

## Comparison with Zettelkasten

| Feature | PARA | Zettelkasten |
|---------|------|-------------|
| Organization | Folders (tree) | Links (network) |
| Atomicity | Notes can vary in size | Atomic (one concept per note) |
| Navigation | Browse by category | Jump via links |
| Best for | Project management, GTD | Academic research, writing |

> This system **combines both**: uses PARA folder structure as the skeleton, and Obsidian's [[bidirectional links]] for Zettelkasten-style networked connections.

## Comparison with GTD

- **GTD** (Getting Things Done) focuses on task management → addresses "how to do it"
- **PARA** focuses on knowledge organization → addresses "where to put it"
- This system uses PARA as the organizational core, with GTD's Next Action embedded in project notes.

## Practical Tips

### Folders vs Tags vs Links
| Dimension | Purpose |
|-----------|---------|
| Folders | Coarse-grained classification (PARA 4-level structure) |
| Tags | Cross-classification dimensions and status (#area, #resource, #todo) |
| Links | Semantic relationships between notes |

### Monthly Review
1. Check `04-Archives` for content to restore
2. Check `01-Projects` for completion or demotion candidates
