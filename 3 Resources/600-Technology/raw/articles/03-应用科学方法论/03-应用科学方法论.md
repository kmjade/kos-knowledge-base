# 03 应用科学方法论

> **UDC 6** —— 本章是 [[01-应用科学概述|01 概念]]、[[02-应用科学史与技术演化|02 史]] 之后的**方法**章：应用科学**怎么做**。
> 目标：把「不确定的真实问题」，变成「可交付、可验证的产物」。

---

## 一、总纲：一条主干

```
问题 → 需求 → 设计 → 实现 → 验证 → 运维/退役
```

> 十壳都走这条主干，只是**领域词汇不同**（医学叫「诊断—治疗方案—疗效评估」，工程叫「需求—设计—验证」，化工叫「小试—中试—放大」）。

| 阶段 | 要产出 | 关键纪律 |
|:--|:--|:--|
| **问题** | 问题陈述 · 边界 | 先**定义对的问题**，再解题 |
| **需求** | 需求规格 · 验收标准 | 可测、可验证 |
| **设计** | 方案 · 接口 · 权衡记录 | 多方案 · 留取舍理由 |
| **实现** | 原型 · 产品 | 先做**最小可行**，再放大 |
| **验证** | 试验报告 · 验收 | 独立性 · 可复现 |
| **运维/退役** | 维护 · 回收 | 全生命周期责任 |

---

## 二、通用方法族

| 方法族 | 代表方法 | 解决什么 |
|:--|:--|:--|
| **需求与问题** | 需求工程 · 用户研究 · 问题定义 | **做对的事** |
| **设计** | 概念设计 · 权衡分析 · TRIZ · DFX（面向制造/装配/成本…） | 把需求变方案 |
| **建模与仿真** | 数学模型 · CAE · 数字孪生 | **先算再造** |
| **实验与测量** | DOE（试验设计）· 误差分析 · 标定 | 让数据说得清 |
| **验证与确认** | V&V（Verification & Validation）· 型式试验 · 验收 | 装对了 + 做对了 |
| **质量与可靠性** | QC/QA · FMEA · 六西格玛 · SPC · 可靠性工程 | 稳定复现 |
| **标准化与合规** | 标准体系 · 认证 · 法规 | 互通与信任 |
| **系统工程** | V 模型 · 需求—架构—验证闭环 · MBSE | 复杂系统的集成 |
| **项目与迭代** | 阶段门（Stage-Gate）· 敏捷 · 配置管理 | 可控推进 |
| **安全与风险** | HAZOP · LOPA · 冗余设计 · 安全完整性等级 | **不出事** |

---

## 三、三类方法的性质

| 类型 | 特征 | 例 | 何时用 |
|:--|:--|:--|:--|
| **确定性** | 可计算、可预测 | 力学计算 · 电路仿真 | 机理清楚 |
| **经验性** | 靠试制、试验 | 试焊 · 台架试验 | 机理复杂 / 经验主导 |
| **统计性** | 靠数据分布 | DOE · SPC · 回归 | 因素多、噪声大 |

> 成熟做法常是**三者叠加**：先算（确定性）→ 再试（经验）→ 用数据收口（统计）。

---

## 四、跨壳通用的五条纪律（不变式）

1. **可复现**：记录过程、版本、标定 —— 别人能重来一遍。
2. **可验证**：任何主张都要有**指标 + 验收方法**。
3. **约束下取舍**：**没有最优解，只有权衡**；写下「为什么这样选」。
4. **安全优先**：先问「**最坏的后果**是什么」，再谈性能与成本。
5. **小步迭代**：原型要快、反馈要短、放大要稳。

---

## 五、常见陷阱

| 陷阱 | 症状 |
|:--|:--|
| 过早收敛 | 没比较方案就选第一个 |
| 过早优化 | 在不确定处精雕细琢 |
| 忽略约束 / 接口 | 单件能跑，一集成即崩 |
| 只测「能测的」 | 指标好看，真实问题没碰 |
| 把 demo 当产品 | 实验室成功 ≠ 可量产 · 可维护 |
| 忽视退役 | 没想「废了怎么办」 |

---

## 核心问题

**在真实约束下，如何用一套可复现的方法，把「想法」变成「可靠产物」？**
