# PARA 与知识管理

> **资源：** PARA 在个人知识管理（PKM）中的深入应用与实践。

---

## 信息流模型

PARA 本质是一个**信息过滤器**，从粗糙的搜集到精炼的知识：

```
采集 → 项目化 → 完成 → 领域化 → 固化认知 → 归档
```

1. **采集阶段** — 闪念笔记、书签、截图 → 放入 `06-Daily` 或 `05-Meta/Inbox`
2. **项目化阶段** — 将相关素材提炼为具体的项目产出
3. **完成阶段** — 项目交付后，提炼可复用的知识
4. **领域化阶段** — 将高频复用的知识提升为领域标准
5. **归档阶段** — 低价值/低频率的知识进入归档

## 与 Zettelkasten 的区别

| 特性 | PARA | Zettelkasten |
|------|------|-------------|
| 组织方式 | 文件夹（树状） | 链接（网状） |
| 原子性 | 笔记可大可小 | 原子化（一概念一笔记） |
| 导航 | 分类浏览 | 链接跳转 |
| 适合场景 | 项目管理、GTD | 学术研究、写作 |

> 本系统**融合两者**：使用 PARA 的文件夹结构作为骨架，使用 Obsidian 的[[双向链接]]实现 Zettelkasten 式的网状连接。

## 与 GTD 的对比

- **GTD** (Getting Things Done) 侧重任务管理 → 解决"如何做"
- **PARA** 侧重知识组织 → 解决"知识放哪里"
- 本系统以 PARA 为组织核心，项目笔记中嵌入 GTD 的 Next Action

## 实践技巧

### 文件夹 vs 标签 vs 链接
| 维度 | 用途 |
|------|------|
| 文件夹 | 粗粒度分类（PARA 四级结构） |
| 标签 | 跨分类的维度和状态（#area, #resource, #todo） |
| 链接 | 笔记之间的语义关联 |

### 月度回顾
1. 检查 `04-Archives` 是否有需要恢复的内容
2. 检查 `01-Projects` 是否完成或需要降级
3. 检查 `02-Areas` 是否还需要持续关注
