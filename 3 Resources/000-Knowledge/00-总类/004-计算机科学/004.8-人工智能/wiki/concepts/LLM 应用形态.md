# LLM 应用形态

> **概念** — 大语言模型在系统中的**使用方式**：从单次提示到自主 Agent，本质是在「模型参数内知识」与「外部系统能力」之间分配职责。

## 两条分类轴

| 轴 | 一端 | 另一端 |
|:--|:--|:--|
| 知识来源 | 参数内知识（预训练） | 外部知识（检索 / 工具 / 数据库） |
| 控制方式 | 单次生成 | 多步自主（规划 · 迭代 · 调用） |

## 形态谱系

| 形态 | 做法 | 适用 | 代价 |
|:--|:--|:--|:--|
| 零样本 / 少样本提示 | 指令 + 示例 | 通用任务、快速验证 | 稳定性依赖提示质量 |
| 上下文学习（ICL） | 上下文内给示例 | 无法微调 | 示例占用上下文 |
| 思维链（CoT） | 显式展开推理 | 多步推理 | token 成本 · 链可能不忠实 |
| 结构化输出 | 约束为 JSON / schema | 系统集成 | 需校验重试 |
| 工具调用 | 模型输出调用意图，系统执行 | 计算 · 查询 · 操作 | 权限与错误处理 |
| 检索增强（RAG） | 先检索再作答 | 私有 / 时效知识 · 可溯源 | 检索质量决定上限 |
| 微调 / PEFT | LoRA · 适配器 | 风格 · 领域 · 格式 | 训练与维护成本 |
| Agent | 自主规划 + 多轮工具调用 | 开放式多步任务 | 不可控 · 成本高 · 需护栏 |

## Agent 构成

```
目标 ─▶ 规划（分解）─▶ 行动（工具 / 检索 / 代码）─▶ 观察
          ▲                                        │
          └──────── 反思 / 重规划 ◀────────────────┘
```

| 组件 | 作用 |
|:--|:--|
| 规划 | 分解 · 排序 · 停止条件 |
| 记忆 | 短期上下文 · 长期外部存储 |
| 工具 | 检索 · 代码执行 · API · 文件系统 |
| 执行循环 | ReAct（推理–行动交替）· Plan-and-Execute |
| 护栏 | 权限 · 预算 · 人工确认 · 沙箱 |

## 组合与选择顺序

| 组合 | 收益 |
|:--|:--|
| RAG + CoT | 先取证据再推理，降低幻觉 |
| 工具 + 微调 | 微调稳定调用格式，工具保证事实性 |
| Agent + RAG | 自主决定检索时机与查询改写 |
| 多 Agent | 角色分工（规划 / 执行 / 评审），协调成本高 |

**经验顺序**：提示 → 检索 → 工具 → 微调 → Agent。越往后**控制力越弱、成本越高**。

## 评估

| 维度 | 关注 |
|:--|:--|
| 任务成功率 | 端到端完成度 |
| 事实性 | 幻觉率 · 引用支撑 |
| 鲁棒性 | 输入扰动 · 提示注入 · 长上下文 |
| 效率 | 时延 · token 成本 · 调用次数 |
| 可控性 | 可中断 · 可回滚 · 可审计 |

> Agent 形态必须保留**执行轨迹（trace）**，否则失败无法定位。
