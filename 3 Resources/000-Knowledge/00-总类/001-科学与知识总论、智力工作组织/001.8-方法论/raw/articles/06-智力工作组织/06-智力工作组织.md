# 06 智力工作组织

> 本库第 06 章。方法论不止「怎么做研究」，还包括**怎么组织做研究的人、流程与工具**：个人笔记 · 文献 · 协作 · 可追溯性。
> 入口：[[001.8-方法论|001.8 方法论]]。上一章：[[05-失效模式|05 常见失效模式]]；下一章：[[07-方法论之争|07 方法论之争]]。

---

## 一、为什么方法论要谈组织

- **认知资源有限**：工作记忆容量小，靠外部结构（笔记、清单、版本）承担记忆与比对。
- **流程即方法**：捕获是否完整、编码是否一致、版本是否可追溯，直接决定结论能否复现。
- **组织反作用于知识**：分类方式决定什么问题容易被看见；工具选择决定哪些证据被保留。
- **个人与集体两层**：个人层面的组织（本章）与集体层面的科研组织（[[001.89-科学与科学工作的组织|001.89]]）相互约束。

## 二、个人层：笔记与文献

| 实践 | 做法 | 目的 |
|:------|:------|:------|
| 原子化笔记 | 一条笔记一个想法 | 可复用 · 可重排 |
| 卡片盒 / Zettelkasten | 编号 + 链接 + 索引 | 让想法之间产生意外连接 |
| 文献管理 | 统一条目 · 全文 · 引用键 | 引用可追溯 · 减少重复 |
| 阅读笔记 | 摘录 + 自己的话 + 质疑 | 区分作者观点与自己的判断 |
| 项目 / 领域分层 | 项目笔记 vs 长期领域笔记 | 短期交付与长期积累分开 |

- 笔记的价值不在**收集量**，而在**重写与连接**：用自己的话重述，才能暴露理解缺口。
- 文献管理的最低要求：每条引用能回到**原文位置**（页码 / 段落 / DOI）。
- 工具会过期，**结构原则**不会：可检索、可链接、可迁移。

## 三、流程层：捕获 → 处理 → 组织 → 表达

| 阶段 | 动作 | 失败表现 |
|:------|:------|:------|
| 捕获 | 收进来（剪藏 · 速记 · 文献） | 只收不看 · 来源丢失 |
| 处理 | 摘要 · 标注 · 判断相关性 | 无限延期 · 囤积 |
| 组织 | 分类 · 链接 · 归档 | 目录越建越细，检索仍靠记忆 |
| 表达 | 写作 · 汇报 · 产出 | 输入很多，输出为零 |

- 与本 vault 的 IOO 流水线对应：`1-input → 2-output → 3-outcome`（输入 → 输出 → 成果）。
- **可中断原则**：任何一步都能停下再继续，不依赖一次长时间专注。
- **可追溯原则**：每个结论能回到来源与日期；修改留有记录。
- **低摩擦原则**：捕获步骤越少，越可能坚持；复杂系统常死于启动成本。

## 四、协作层

| 机制 | 作用 | 最低做法 |
|:------|:------|:------|
| 预注册 | 锁定假说与分析计划 | 公开时间戳版本 |
| 数据共享 | 支持复现与再利用 | 脱敏 · 文档 · 许可 |
| 代码共享 | 分析可复跑 | 版本控制 · 环境说明 |
| 贡献署名（CRediT） | 明确角色 | 投稿时如实填写 |
| 版本控制 | 追踪修改 | Git / 云盘历史 |
| 评审记录 | 保存判断依据 | 评审意见与回应归档 |

- 协作的核心不是「沟通多」，而是**接口清楚**：谁产出什么、以什么格式交接、何时冻结。
- 多人研究的常见断点：数据格式不统一、命名随意、口径变化无记录。

## 五、工具层

| 类别 | 代表 | 选择标准 |
|:------|:------|:------|
| 参考管理 | Zotero · EndNote | 引用键稳定 · 可导出 |
| 知识库 | Obsidian · Logseq | 纯文本 · 双链 · 可迁移 |
| 版本控制 | Git | 差异可读 · 可回溯 |
| 数据分析 | R · Python | 脚本化 · 可复跑 |
| 自动化 | 脚本 · 模板 | 减少重复 · 可审计 |

- 工具选择三问：**数据能否导出？十年后还能打开吗？换工具成本多大？**
- 自动化要保留**中间产物**：全自动黑箱会削弱核查能力。
- 工具不是方法论；用 Obsidian 不等于会思考，用 Zotero 不等于读过文献。

## 六、组织设计原则

1. **可追溯**：来源、版本、修改理由齐全。
2. **可复用**：模板、术语表、编码手册共享。
3. **可中断**：任务拆到能在一次专注内完成。
4. **低摩擦**：启动与维护成本低。
5. **可迁移**：不锁定在单一软件或平台。

> 判断一个知识系统好不好，看它**在压力下**是否还能运转：临近截止日期时，你还会用它吗？

## 七、与实践层的边界

- 本章讲**原理与结构**：为什么原子化、为什么要可追溯、流程如何设计。

## 八、五个常见误读

| 误读 | 纠正 |
|:------|:------|
| 工具 = 方法 | 工具只是载体；方法与判断才决定质量 |
| 收集 = 理解 | 收藏是输入，重写与连接才是理解 |
| 体系越复杂越好 | 复杂度要匹配使用频率与维护能力 |
| 笔记必须永久保存 | 有生命周期；过期内容应归档或删除 |
| 组织是个人习惯 | 在团队中，组织方式是协作接口与复现条件 |
