> 本库第 09 章，也是收官章。第 02 章给了生命周期的骨架；本章追问：**文档如何跨越时间仍然可信、可读、可理解**。

## 一、生命周期：从线性到连续

| 模型 | 形态 | 主张 |
|:------|:------|:------|
| **生命周期**（life cycle） | 创建 → 使用 → 归档 → 保存 → 处置 | 阶段分明，便于制度设计 |
| **连续体**（continuum） | 创建 · 捕获 · 组织 · 多元使用，四维同时发生 | 归档动作在创建时已开始 |

- 阶段模型适合**责任划分**：谁在什么阶段做什么。
- 连续体模型适合**设计**：保存要求（格式 · 元数据 · 标识）必须在创建时就满足。
- 实践结论：**保存不是最后一步，而是从创建开始的一组约束**。

## 二、版本管理与可追溯

| 问题 | 表现 | 做法 |
|:------|:------|:------|
| **哪一版是当前版** | 文件副本泛滥 | 版本号 · 状态标记（草稿 / 定稿 / 发布） |
| **改了什么** | 无变更记录 | 变更日志 · 版本差异 |
| **为什么改** | 只留结果不留理由 | 提交说明 · 决策记录 |
| **能否回到旧版** | 覆盖保存 | 版本控制 · 快照 |
| **能否引用某一版** | 版本不可定位 | 版本化标识（DOI 版本 · 版本号） |

- **语义化版本**（major.minor.patch）适合软件；文档常用日期 + 状态 + 修订号。
- **版本控制的前提是单一权威源**：多份并行副本会让「当前版」失效。
- 可追溯性 = **标识（哪一版）+ 记录（改了什么）+ 理由（为什么改）** 三件套。

## 三、数字保存的威胁模型

| 威胁 | 机制 | 早期信号 |
|:------|:------|:------|
| **介质老化 / 比特腐坏** | 磁盘、磁带、光盘随时间产生静默错误 | 校验失败 · 文件打不开 |
| **格式过时** | 专有格式失去读取器 | 厂商停止支持 · 文档打不开 |
| **软件依赖** | 需要特定版本的应用或插件 | 系统升级后失效 |
| **链接失效** | 外部引用、字体、脚本下线 | 404 · 资源缺失 |
| **机构消亡** | 托管方停止服务或倒闭 | 服务公告 · 迁移通知 |
| **人为错误** | 误删、覆盖、错误迁移 | 审计日志缺失 |
| **恶意攻击** | 勒索软件、篡改、删除 | 完整性校验异常 |

- 「数字黑暗时代」不是科幻：**没有维护的数字对象，寿命以年计**。
- 威胁不是单点的，而是**叠加**的：格式过时 + 机构消亡往往同时发生。
- 威胁模型决定保存策略：针对比特 → 校验与复制；针对格式 → 迁移或仿真；针对机构 → 分布式保存。

## 四、三种保存策略

| 策略 | 做法 | 优点 | 风险 |
|:------|:------|:------|:------|
| **迁移**（migration） | 定期转换为新格式 / 新载体 | 保持可读、可用现有工具 | 每次转换都可能引入变化 |
| **仿真**（emulation） | 保留原格式，模拟旧运行环境 | 保留原始体验与行为 | 仿真器本身也会过时 |
| **封装**（encapsulation） | 把文件、元数据、说明、必要工具打包 | 自描述、可延迟处理 | 包内工具仍需可运行 |

- **技术保存**（technology preservation）：保留旧硬件与软件，成本高，只适合少量特殊藏品。
- 策略选择取决于**对象性质**：文本适合迁移；交互式作品、软件、游戏更依赖仿真。
- **迁移必须记录**：谁迁的、从什么格式到什么格式、校验值变化 —— 否则真实性无法证明。

## 五、OAIS 参考模型

**OAIS**（ISO 14721）是数字保存的通用参考框架：

| 信息包 | 含义 |
|:------|:------|
| **SIP**（Submission Information Package） | 提交给保存系统的包 |
| **AIP**（Archival Information Package） | 长期保存的包（内容 + 保存元数据） |
| **DIP**（Dissemination Information Package） | 提供给用户的包 |

六个功能实体：

| 功能 | 职责 |
|:------|:------|
| **摄取**（Ingest） | 接收、校验、生成 AIP |
| **档案存储**（Archival Storage） | 介质管理、复制、校验 |
| **数据管理**（Data Management） | 元数据与检索 |
| **访问**（Access） | 提供 DIP、权限控制 |
| **保存规划**（Preservation Planning） | 监测格式与技术变化、制定迁移计划 |
| **行政管理**（Administration） | 政策、合同、审计 |

- **可信数字仓储**（TDR，ISO 16363）在 OAIS 之上给出审计与认证标准。
- OAIS 的价值不在术语，而在**把「保存」拆成可分工、可审计的职能**。

## 六、备份、复制与分布式保存

| 实践 | 内容 | 防的是什么 |
|:------|:------|:------|
| **3-2-1 原则** | 3 份副本 · 2 种介质 | 单点故障 |
| **异地副本** | 至少一份在不同地点 | 灾害 |
| **定期校验** | 哈希比对、抽样读取 | 比特腐坏 |
| **版本快照** | 保留历史版本 | 误删 / 篡改 |
| **分布式保存** | LOCKSS · CLOCKSS · Portico | 机构消亡 |

- **备份 ≠ 保存**（第 02 章）：备份解决「副本丢失」，保存解决「格式与理解失效」。
- **复制不等于可信**：副本必须可校验、可追溯来源，否则只是「多了一份不确定的文件」。
- 云存储解决部分介质问题，但引入**服务依赖与条款风险**；云不是保存策略的终点。

## 七、真实性与完整性维持

| 目标 | 手段 | 说明 |
|:------|:------|:------|
| **完整性** | 哈希 · 校验和 | 证明比特未变 |
| **真实性** | 来源记录 · 签名 · 时间戳 | 证明是谁、何时形成 |
| **可理解性** | 元数据 · 文档说明 · 格式说明 | 证明未来的人能看懂 |
| **可用性** | 迁移 · 仿真 · 访问接口 | 证明现在能用 |

- **保存元数据**（preservation metadata）是保存工作的核心产物：格式、来源、迁移历史、权利、校验值。
- **可信副本**（trusted copy）：经过校验、来源清晰、迁移有记录的副本，可替代原件提供使用。
- **不可理解的数据等于没保存**：只留字节、不留上下文，未来无法解释。

## 八、鉴定与处置

| 决策 | 内容 | 注意 |
|:------|:------|:------|
| **保留期限** | 法定 · 业务 · 历史价值 | 法律义务归 UDC 34 |
| **鉴定**（appraisal） | 判断哪些值得长期保存 | 价值判断，难以逆转 |
| **抽样** | 海量数据按比例保留 | 抽样规则须记录 |
| **销毁** | 到期删除或物理销毁 | 不可逆 · 须授权与记录 |
| **移交** | 转交档案馆 / 机构库 | 责任与元数据一并移交 |

- **处置是不可逆决策**：销毁前必须确认没有法定保留义务与历史价值。
- 个人数据与隐私会影响保留决策；「全部永久保留」既不可行也不合规。
- 处置记录本身也是档案：销毁了什么、何时、依据什么。

## 九、个人与小型知识库的保存实践

| 实践 | 做法 | 收益 |
|:------|:------|:------|
| **格式选择** | 优先开放、纯文本、广泛支持的格式 | 降低格式过时风险 |
| **单一权威源** | 一处主库，其余为备份 | 避免版本分裂 |
| **版本控制** | Git / 历史记录 / 快照 | 可回溯、可审计 |
| **命名与元数据** | 稳定命名 + frontmatter 元数据 | 可检索、可迁移 |
| **链接策略** | 优先持久标识（DOI），附存档副本 | 降低链接失效 |
| **定期校验** | 备份校验、抽样打开 | 及早发现腐坏 |
| **迁移计划** | 定期评估格式与工具 | 避免被动抢救 |

- 小型知识库的最大风险不是技术，而是**无人维护**：保存是一项持续承诺，不是一次性动作。
- 「能打开」只是最低标准；**能理解、能引用、能证明未被篡改**才是保存完成。

## 十、五个常见误读

1. **「有备份就等于保存好了」** —— 备份防丢失，不防格式过时与理解失效。
2. **「放在云上就永久安全」** —— 云引入服务依赖与条款风险，仍需本地与迁移策略。
3. **「打印出来最永久」** —— 纸张也会老化，且丢失可检索性、链接与交互行为。
4. **「迁移会改变文档，所以不能迁移」** —— 有记录的迁移仍保持同一性；不迁移才会失传。
5. **「保存就是什么都不动」** —— 保存是持续维护：校验、复制、迁移、记录。

## 本章要点

- 生命周期模型（线性）与连续体模型（多维）互补；**保存从创建开始**。
- 可追溯 = 标识 + 变更记录 + 变更理由；版本控制的前提是单一权威源。
- 数字保存威胁是叠加的：比特腐坏 · 格式过时 · 软件依赖 · 链接失效 · 机构消亡 · 人为与恶意破坏。
- 三种策略：**迁移 · 仿真 · 封装**；迁移必须记录，否则真实性无法证明。
- **OAIS**（SIP / AIP / DIP + 六功能）把保存拆成可分工、可审计的职能；TDR 提供认证。
- **备份 ≠ 保存**；3-2-1 · 异地 · 校验 · 快照 · 分布式保存各防不同风险。
- 保存的目标是**完整 · 真实 · 可理解 · 可用**；只留字节不算保存。
- 处置不可逆，须有授权与记录；个人知识库的最大风险是无人维护。
