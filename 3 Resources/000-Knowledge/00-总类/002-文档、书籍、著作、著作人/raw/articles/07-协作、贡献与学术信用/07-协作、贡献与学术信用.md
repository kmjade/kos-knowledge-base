# 07 协作、贡献与学术信用

> 本库第 07 章。第 06 章讲了谁署名；本章讲**多人协作时贡献如何被描述、信用如何被分配、责任如何被追究**。

## 一、从个人作者到团队科学

现代研究越来越难由一人完成：

| 变化 | 表现 | 对署名的压力 |
|:------|:------|:------|
| **大科学** | 高能物理、基因组、气候模型的超大型协作组 | 作者列表达数百至数千人 |
| **跨学科** | 计算 + 生物 + 临床 + 伦理 | 贡献类型无法用「第一 / 末位」概括 |
| **数据密集** | 数据采集、清洗、标注成为独立贡献 | 这些劳动常不进入署名 |
| **工具化** | 软件、平台、模型成为研究基础设施 | 「写代码」是否算学术贡献 |

- 作者列表变长后，**署名顺序承载的信息量下降**：中间作者的位置几乎不传递贡献信息。
- 结果是制度补丁：贡献声明、共同一作、协作组署名、贡献者模型。

## 二、CRediT：贡献角色分类

**CRediT**（Contributor Roles Taxonomy）把贡献拆成 14 类角色：

| # | 角色 | 含义 |
|:-:|:------|:------|
| 1 | **Conceptualization** | 构思、研究目标与问题形成 |
| 2 | **Data curation** | 数据管理、清洗、标注、维护 |
| 3 | **Formal analysis** | 统计、数学、计算分析 |
| 4 | **Funding acquisition** | 争取资助 |
| 5 | **Investigation** | 执行研究、实验、访谈、观察 |
| 6 | **Methodology** | 设计方法、模型、协议 |
| 7 | **Project administration** | 项目管理与协调 |
| 8 | **Resources** | 提供样本、设备、材料、算力 |
| 9 | **Software** | 编程、实现、算法开发 |
| 10 | **Supervision** | 指导、监督、领导 |
| 11 | **Validation** | 结果验证、复现 |
| 12 | **Visualization** | 图表、可视化呈现 |
| 13 | **Writing – original draft** | 初稿撰写 |
| 14 | **Writing – review & editing** | 审阅、修订、编辑 |

- 每个角色可标注强度：**Lead（主导）· Equal（同等）· Supporting（支持）**。
- CRediT 是**角色描述，不是贡献计量**：它说明「做了什么」，不说明「做了多少」。
- 它解决的是「贡献不可见」，不是「贡献如何折算成分数」。
- 采用情况因期刊与学科而异；部分期刊强制要求，部分仅鼓励。

## 三、从作者身份到贡献者身份

学界长期存在「authorship vs contributorship」之争：

| 模型 | 主张 | 优点 | 局限 |
|:------|:------|:------|:------|
| **作者模型** | 达到标准者列为作者，其余致谢 | 责任明确、制度成熟 | 二元划分，贡献信息少 |
| **贡献者模型** | 所有贡献者按角色记录，弱化「作者」门槛 | 信息完整、包容技术劳动 | 责任归属模糊、评价体系未跟上 |

- 折中做法：**保留作者制度 + 强制贡献声明**（CRediT 即此路线的产物）。
- 贡献者模型在软件、数据、公民科学中更常见（提交记录、issue、review 本身就是贡献日志）。
- 无论哪种模型，**「能承担责任」仍是底线**（见第 06 章 ICMJE 第 4 条）。

## 四、署名顺序的学科差异

| 学科 | 惯例 | 后果 |
|:------|:------|:------|
| **生物医学** | 第一作者 = 主要执行者；末位 = 资深指导者 | 中间作者贡献不可见 |
| **计算机科学** | 会议论文第一作者权重高；常按贡献排序 | 通讯作者概念较弱 |
| **经济学 / 数学** | 字母序 | 顺序不传递贡献信息，靠贡献声明 |
| **人文社科** | 独著为主；合著较少 | 署名争议相对少 |
| **大型协作** | 协作组署名 + 成员列表 | 个人信用依赖内部政策 |

- **共同第一作者**的普及稀释了「第一作者」信号；标注需全体同意。
- 字母序并非更公平：它把贡献差异完全隐藏，评价只能依赖外部信息。
- 署名惯例是**地方性制度**，跨学科合作时须事先约定。

## 五、致谢的结构

致谢不是「作者之外的人」，而是**未达作者标准的贡献**：

| 致谢对象 | 典型内容 | 注意 |
|:------|:------|:------|
| **技术协助** | 实验操作、样品制备、语言润色 | 需本人同意被致谢 |
| **数据 / 材料提供** | 数据集、样本、设备 | 区分「提供」与「共同设计」 |
| **资金支持** | 基金编号、资助机构 | 通常单独设 Funding 声明 |
| **机构支持** | 平台、算力、场地 | 与作者单位区分 |
| **审稿人** | 匿名评审意见 | 一般匿名致谢或不致谢 |
| **编辑** | 处理编辑、客座编辑 | 视期刊惯例 |

- **致谢 ≠ 作者**：致谢者不承担责任，也不获得引用信用。
- **利益冲突声明**（COI）与致谢是两件事：前者披露关系，后者承认帮助。
- 资金声明必须可核查：基金编号错写会导致成果无法归集。

## 六、学术信用的计量

| 指标 | 计算 | 用途 | 局限 |
|:------|:------|:------|:------|
| **引用次数** | 被引频次 | 影响力近似 | 学科差异 · 自引 · 负面引用 |
| **h-index** | 有 h 篇论文各被引至少 h 次 | 个人产出与影响 | 忽略作者位置 · 年龄偏差 |
| **影响因子** | 期刊前两年论文的平均被引 | 期刊层面 | 不能代表单篇或作者 |
| **Altmetrics** | 社交媒体、下载、政策引用 | 社会影响补充 | 噪声大 · 易操纵 |
| **作者位置加权** | 按第一 / 通讯 / 中间加权 | 修正署名差异 | 权重主观 |

- **指标是代理，不是目标**：任何单一指标都可被优化（Goodhart 定律）。
- **DORA（2012）**与 **Leiden Manifesto（2015）**主张：评价应看研究内容与多样贡献，而非仅看期刊指标。
- 负责任评价（responsible research assessment）强调**定性评议 + 多源证据**。

## 七、团队中的信用分配

| 问题 | 表现 | 机制 |
|:------|:------|:------|
| **中间作者不可见** | 大量实际工作没有信号 | 贡献声明 · 贡献者模型 |
| **技术劳动被低估** | 数据、软件、管理不算「学术」 | CRediT 明确列为角色 |
| **资深者通吃** | 末位作者获得过多信用 | 评价改革 · 贡献权重 |
| **团队 vs 个人** | 大型协作的成果如何归属个人 | 协作组内部政策 · 成员列表 |
| **马太效应** | 已有声望者获得更多信用 | 匿名评审 · 盲评 · 结构化评价 |

- **信用分配（credit allocation）是制度设计问题**，不是道德问题；只靠个人自觉无法解决。
- 透明记录（贡献声明、版本历史、预注册）是减少争议的最低成本手段。

## 八、学术不端与作者责任

| 类型 | 行为 | 责任归属 |
|:------|:------|:------|
| **剽窃**（plagiarism） | 未注明使用他人文字、想法、数据 | 署名者共同承担，执笔者责任更重 |
| **伪造 / 篡改** | 编造数据、修改图像 | 直接责任人 + 通讯作者 |
| **重复发表** | 同一成果多次发表 | 全体作者 |
| **作者身份买卖** | 挂名、代写、论文工厂 | 买卖双方 |
| **引用操纵** | 强制引用、 citation cartel | 作者与编辑 |
| **隐瞒利益冲突** | 未披露资助或商业关系 | 全体作者 |

- **ICMJE 第 4 条**要求全体作者对整体工作负责：这使「不知情」难以成为免责理由。
- **撤稿**（retraction）是正式纠正机制；**更正**（correction）用于非根本性错误。
- COPE 提供处理流程：调查、作者回应、机构介入、公开通知。
- 学术不端的**认定**属机构与出版方；法律后果（诽谤、欺诈、著作权）归 UDC 34 法律。

## 九、协作中的可审计记录

| 实践 | 作用 | 工具示例 |
|:------|:------|:------|
| **版本控制** | 记录谁在何时改了什么 | Git · 文档历史 |
| **贡献日志** | 把日常劳动转成可核查记录 | issue · commit · 代码评审 |
| **预注册** | 事先固定假设与分析计划 | OSF · ClinicalTrials |
| **贡献声明** | 发表时固定角色 | CRediT |
| **持久标识** | 把成果与身份绑定 | ORCID · DOI（见第 04 章） |

- **可审计**是可信协作的基础：没有记录，贡献争议只能靠记忆与权力。
- 这些实践同时服务于**可复现性**：记录越完整，复现与验证越容易。

## 十、五个常见误读

1. **「CRediT 能算出贡献比例」** —— 它只描述角色与强度，不提供计量。
2. **「作者越多，每人贡献越小」** —— 贡献结构不同，不能按人数平均。
3. **「致谢等同于作者」** —— 致谢者不承担责任，也不获得引用信用。
4. **「h-index 高就等于研究好」** —— 指标受学科、年龄、自引与引用文化影响。
5. **「通讯作者只是联络人」** —— 通讯作者承担投稿、质询与数据可获取性的实质责任。

## 本章要点

- 团队科学使署名顺序的信息量下降，制度补丁是**贡献声明 + 贡献者模型**。
- **CRediT 14 角色**描述「做了什么」与强度（Lead / Equal / Supporting），不计量「做了多少」。
- 作者模型（二元）与贡献者模型（连续）各有局限；主流折中是「作者 + 强制贡献声明」。
- 署名顺序有强烈学科差异（贡献序 / 字母序 / 协作组），跨学科合作须事先约定。
- 致谢承认未达作者标准的贡献；**致谢 ≠ 作者**，且与利益冲突声明分开。
- 引用数 · h-index · 影响因子 · Altmetrics 都是代理指标；DORA 与 Leiden Manifesto 主张负责任评价。
- 学术不端的责任落在全体作者；ICMJE 第 4 条使「不知情」难以免责。
- 可审计记录（版本控制 · 贡献日志 · 预注册 · 贡献声明 · 持久标识）是可信协作的基础。
