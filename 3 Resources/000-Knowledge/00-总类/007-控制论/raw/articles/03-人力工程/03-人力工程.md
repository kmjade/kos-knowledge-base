# 03 人力工程

> **支线 03 / UDC 007** — 人力工程（Human Engineering / Human Factors / Ergonomics）：把人视为系统的**一个部件**，研究其能力边界、信息加工与失误机理，并据此设计人机界面与任务。
> 所属：[[007-控制论|007 控制论]]（支线 03）。
> 落位：`007-控制论/raw/articles/03-人力工程/`。
> 关注「人怎么感知、决策、操作，系统怎么配合人」，不涉及回路稳定性（→ 支线 01）与系统的一般结构（→ 支线 02）。

---

## 一、领域定位

三个近义词各有侧重，常混用：

| 名称 | 侧重 | 典型场景 |
|:--|:--|:--|
| **Human Factors**（人因） | 认知与行为科学视角 | 航空、医疗、控制室 |
| **Ergonomics**（工效学） | 人体测量、生理与作业环境 | 工位、工具、体力作业 |
| **Human Engineering**（人力工程） | 工程设计中的人机匹配 | 装备、界面、操作规程 |

共同前提：**人不是可以无限适应机器的柔性部件**。系统的可靠性上限，往往由人的信息处理瓶颈决定。

## 二、人机系统

经典模型把作业拆成「人—机—环境」三角，并套用与支线 01 同构的回路：

```
感知（显示器） → 判断（人的信息处理） → 操作（控制器） → 机器/过程 → 反馈 → 感知 …
```

| 环节 | 人的角色 | 设计问题 |
|:--|:--|:--|
| 感知 | 读表、听警报、看态势 | 信息是否可见、可辨、可分级？ |
| 判断 | 诊断、决策、优先级排序 | 信息量是否超出工作记忆？ |
| 操作 | 按键、操纵杆、语音 | 控制是否可达、兼容、防误触？ |
| 反馈 | 确认动作已生效 | 是否有明确、及时的回执？ |

> **分配问题**：哪些功能交给人、哪些交给自动化？答案取决于**速度、精度、重复性**与**异常处理、价值判断**的相对优势，而非「谁更先进」。

## 三、人的信息处理

| 环节 | 特征 | 设计含义 |
|:--|:--|:--|
| 感觉登记 | 视/听通道容量有限，并行度低 | 关键信息不跨通道争抢 |
| 注意 | 选择性、持续性、分配有限 | 避免长时间单调监视 |
| 工作记忆 | 容量小（约 4±1 组块）、易 decay | 减少「记住再操作」 |
| 长时记忆 | 容量大但提取依赖线索 | 用可识别代替需回忆 |
| 决策 | 受启发式与偏差影响 | 提供比较基准与默认值 |
| 反应 | 受刺激—反应兼容性影响 | 控制方向与显示方向一致 |

**信号检测论**把「看见」拆成两个独立参数：**敏感性 d′**（能否分辨信号与噪声）与**判据 β**（愿意多冒险还是多保守）。界面设计能改变 d′，激励与后果则改变 β。

## 四、工作负荷与绩效

| 概念 | 说明 |
|:--|:--|
| **资源模型** | 注意力是有限资源；多任务共享同一资源池会互相挤占 |
| **倒 U 曲线**（Yerkes–Dodson） | 唤醒/负荷过低则无聊，过高则崩溃，中等最佳 |
| **心理负荷** | 可用主观量表、次任务法、生理指标测量 |
| **疲劳与警觉性下降** | 长时间监视任务中，漏检率随时间上升 |
| **情境意识**（Situation Awareness） | 对「当前发生了什么、接下来会怎样」的持续把握 |

> 设计目标不是「让人更努力」，而是**让峰值负荷落在人的可控区间**，并把低谷期的注意力需求降下来。

## 五、人因失误

Reason 的分类至今通用：

| 类型 | 机制 | 例 |
|:--|:--|:--|
| **Slip**（失手） | 意图正确，执行出错 | 按错相邻按钮 |
| **Lapse**（失神） | 意图正确，步骤遗漏 | 忘了复位 |
| **Mistake**（失误） | 意图本身错误 | 选错处置方案 |
| **违规**（violation） | 明知规则而偏离 | 图省事跳过检查 |

**瑞士奶酪模型**：事故不是单点失败，而是多层防护的漏洞恰好对齐。因此改进重点在**系统防御**（冗余、强制功能、可恢复性），而非仅归咎个人。

> **自动化悖论**：自动化越可靠，人越少练习手动技能；一旦自动化失效，人反而更难接管（out-of-the-loop 问题）。

## 六、工效学设计

| 面 | 要点 |
|:--|:--|
| 显示 | 分组、层级、编码一致；警报分级且不泛滥 |
| 控制 | 可达、可辨、防误触；紧急操作需物理区分 |
| 兼容性 | 刺激—反应、空间、运动方向一致（如向上拨 = 增大） |
| 认知工效 | 减少记忆负担，外化为清单、提示与默认值 |
| 物理工效 | 人体测量百分位、姿势、照明、噪声、温湿度 |
| 可达性 | 面向能力差异的通用设计（Universal Design） |

## 七、自动化与人的角色

| 自动化等级 | 人的角色 | 风险 |
|:--|:--|:--|
| 手动 | 全程操作 | 负荷高、易疲劳 |
| 辅助 | 监控 + 关键决策 | 注意力漂移 |
| 部分自动化 | 监督、异常接管 | 技能退化、接管延迟 |
| 高度自动化 | 例外处理者 | 情境意识丧失、信任失调 |

**信任校准**是关键：过度信任导致滥用（misuse），信任不足导致弃用（disuse）。理想状态是信任与系统实际可靠性**相匹配**。

> 人机共驾、临床决策支持、工业报警系统，都落在同一组问题上：**谁在什么时候拥有最终决定权，以及人能否在需要时真正接手**。

## 八、研究方法

| 方法 | 用途 |
|:--|:--|
| 任务分析 / 层次任务分析（HTA） | 拆解作业步骤与依赖 |
| 认知任务分析（CTA） | 还原专家的判断与知识结构 |
| 人因实验 | 操纵变量、测量绩效与负荷 |
| 仿真与可用性测试 | 在受控条件下暴露界面问题 |
| 事故与近失事件分析 | 从真实失效反推设计缺陷 |

## 十、核心问题

> 当系统越来越自动化，人应当承担哪些功能、界面应如何呈现、又怎样保证人在关键时刻仍能真正接管？
