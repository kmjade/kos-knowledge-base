# 07 方法与实战

> Obsidian 是「工具」，方法是「用法」，实战是「用法落地」。方法与实战本是一枚硬币的两面：方法靠实战验证，实战靠方法成形，故合为一章。

## 方法论

### PARA

由 Tiago Forte 提出，按「可执行性」组织：

| 文件夹 | 含义 |
|--------|------|
| Projects | 有目标、有期限 |
| Areas | 长期负责的领域 |
| Resources | 参考资料 |
| Archives | 归档 |

> 本知识库（KOS_LLM-Wiki）即以 PARA 为骨架。

### Zettelkasten（卡片盒笔记法）

卢曼的学术写作方法：

| 要素 | 说明 |
|------|------|
| 原子笔记 | 一张卡一件事，自成一体 |
| Folgezettel | 卡片间的顺序链接 |
| Hub / 索引 | 主题入口页 |
| 永久笔记 | 用自己的话重写，而非摘抄 |

Obsidian 的 Wikilink 天然契合 Zettelkasten 的「卡片互联」。

### LYT（Linking Your Thinking）

Nick Milo 提出的方法，核心是 **MOC（Map of Content）**：

- MOC 是某个主题的「内容地图」，手动编排相关笔记入口
- 强调「链接 + 地图」而非严格层级文件夹

### 第二大脑（Building a Second Brain）

用 CODE 流程把信息变成可复用的知识资产：

| 步骤 | 含义 |
|------|------|
| Capture | 捕获（剪藏、闪念） |
| Organize | 组织（PARA） |
| Distill | 提炼（渐进式总结） |
| Express | 表达（产出） |

## 实战案例

### 案例总览

| 场景 | 核心方案 | 关键组件 |
|------|----------|----------|
| 学术写作 | Zettelkasten + 文献笔记 | Wikilink + 标签 |
| 项目管理 | PARA + 任务追踪 | Tasks 插件 + 属性 |
| 个人知识库 | PARA + MOC | 文件夹 + MOC |
| 会议记录 | Bases 数据库 | .base + 属性 |
| 日记/周期笔记 | 日/周/月模板 | Templater + Calendar |

### 学术写作（Zettelkasten）

```
文献笔记（摘抄 + 来源）
    ↓ 用自己的话重写
永久笔记（一张卡一件事）
    ↓ Folgezettel 链接
主题 Hub → 论文初稿
```

- 每篇文献一个笔记，标注来源与页码
- 永久笔记用 `[[链接]]` 关联观点
- 写作时沿链接链聚合素材

### 项目管理（PARA）

```
1 Projects/（进行中的项目）
2 Areas/（长期领域）
3 Resources/（参考资料）
4 Archives/（归档）
```

- 项目笔记含 frontmatter：`status`、`priority`、`deadline`
- 用 Dataview 生成「活跃项目」仪表盘
- 用 Tasks 插件追踪待办

### 个人知识库（本库 KOS 范例）

本知识库（KOS_LLM-Wiki）就是一个 Obsidian 实战范例：

- PARA 骨架 + UDC 分类 + LLM-Wiki 知识图谱
- 概念页 / 实体页 / 来源页三类型
- AI 代理（KOS 引擎）自动分拣、编译、校验
- frontmatter `方法论模式` 字段（para / lyt / zettel / generic）正是 PARA + MOC + 原子笔记这套混合的落地

### 会议记录（Bases）

用 Bases 把会议笔记变成可查询数据库：

```yaml
# 会议笔记 frontmatter
---
type: meeting
date: 2026-09-05
attendees: [张三, 李四]
status: 待办
---
```

- 建 `.base` 文件：按 `status` 分组、按 `date` 排序
- 嵌入 `![[会议库.base]]` 生成看板

### 日记 / 周期笔记

| 周期 | 模板内容 |
|------|----------|
| 日记 | 待办、日程、闪念 |
| 周记 | 本周回顾、下周计划 |
| 月记 | 目标达成、复盘 |

用 Templater 自动填充日期与标题，Calendar 插件可视化日历。
