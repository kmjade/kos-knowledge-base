# 08 高级与优化

## 显存与内存管理

| 环境变量 | 作用 |
|------|------|
| `OLLAMA_KEEP_ALIVE` | 模型驻留时长（如 `5m`、`-1` 常驻） |
| `OLLAMA_NUM_PARALLEL` | 并行请求数 |
| `OLLAMA_MAX_LOADED_MODELS` | 同时加载模型数 |
| `OLLAMA_FLASH_ATTENTION` | 启用 Flash Attention（省显存） |

## GPU 优化

- **NVIDIA**：确保安装 CUDA 驱动，Ollama 自动检测
- **Apple Silicon**：Metal 自动启用，统一内存可跑大模型
- **多 GPU**：`OLLAMA_DEVICE` / 自动层分配到多卡
- **量化选择**：显存紧用 `q4_K_M`，显存足用 `q8_0`/`f16` 提质量

## 上下文窗口

- 默认 `num_ctx` 较小，长文本需调大（如 `num_ctx 32768`）
- 更大的 `num_ctx` 消耗更多 KV 缓存显存

## 并发与吞吐

- `OLLAMA_NUM_PARALLEL` 提高并行请求数
- 生产场景考虑 vLLM/TGI 等高吞吐引擎替代
- 缓存：`ollama` 对重复前缀有 KV 缓存优化

## 生产部署模式

| 模式 | 说明 |
|------|------|
| 单机服务 | `ollama serve` + 反向代理（Nginx） |
| Docker | 镜像 + 卷持久化模型 |
| 集群 | 多实例 + 负载均衡 |
| 安全 | 限制 API 暴露、加认证网关 |

## 常见问题

- **加载慢**：首次加载模型到显存较慢，`OLLAMA_KEEP_ALIVE=-1` 常驻可避免
- **OOM**：换更小量化或更小模型
- **CPU 慢**：量化 + 减少 `num_ctx`
