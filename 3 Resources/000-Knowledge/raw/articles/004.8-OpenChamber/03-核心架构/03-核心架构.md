# 03 核心架构

## 总览：一个服务端，多个客户端

```
┌─────────────── 客户端（可替换） ───────────────┐
│ Desktop │ Web/PWA │ VS Code 扩展 │ iOS/Android │
└───────────────┬────────────────────────────────┘
                │ HTTP / WebSocket
┌───────────────▼────────────────────────────────┐
│           OpenChamber 实例（服务端）             │
│  · 会话存储与状态机                              │
│  · Session Goals 审计循环                        │
│  · Multi-run / Fusion 编排                       │
│  · Changes Walkthrough 生成与缓存                │
│  · Preview / dev server 代理                     │
│  · 设备令牌与配对管理                            │
├────────────────────────────────────────────────┤
│           OpenCode SDK（agent 运行时）           │
│  · 模型 provider 调用 · 工具执行 · 文件修改       │
└────────────────────────────────────────────────┘
                │
        模型服务商 / 本地模型
```

理解这张图的关键：**OpenChamber 是服务端，不是客户端应用**。浏览器标签、手机、桌面窗口都只是连接到实例的视图。

## 实例（Instance）

| 属性 | 说明 |
|------|------|
| 定义 | 一个运行在你掌控机器上的 OpenChamber 服务进程 |
| 位置 | Mac / Linux 机器或自有服务器 |
| 会话归属 | 会话存在实例上；关闭客户端、锁屏、换设备都不影响 |
| 默认监听 | `127.0.0.1`，即仅本机 |
| 对外暴露 | 需显式 `--lan` 或经隧道 / Relay |
| 多实例 | 桌面应用可同时连接本地与远程多个实例，并在应用内切换 |

> 这解释了「跨设备接续」为何可行：**状态在服务端，客户端只是渲染层**。

## 服务端承担的后台工作

以下能力都在**服务端**运行，不依赖浏览器标签是否打开：

| 能力 | 服务端职责 |
|------|-----------|
| Session Goals | 每轮结束后调用审计模型、决定继续 / 完成 / 受阻、发送续跑提示 |
| 定时任务 | 按 cron / 每日 / 每周触发会话 |
| Changes Walkthrough | 生成、缓存、失效检测 |
| Preview | 探测本机监听端口、为远程实例建立本地端口转发 |
| 配对与 Relay | 维护 outbound 连接、设备令牌、链路状态 |

## 与 OpenCode 的边界

| 职责 | OpenChamber | OpenCode |
|------|-------------|----------|
| 模型 provider 与密钥 | 读取 / 选择 | **配置与持有** |
| 工具调用、文件读写 | 展示与审批 | **执行** |
| 会话存储 | **持久化与跨端同步** | 提供会话 API |
| 目标循环 | **审计与续跑** | 不感知 |
| 并行 worktree | **编排** | 在对应 worktree 中执行 |
| Git / GitHub | **UI 与集成** | 不负责 |

> 结论：升级 OpenCode 会直接影响 OpenChamber 的能力边界；OpenChamber 的版本节奏与 OpenCode 的 API 稳定性强耦合。
>
> 补充：官方提供 **Claude Code 集成**（经 Claude Agent SDK 与 Claude Code CLI 使用 Pro/Max 订阅），但它只把 Claude 接入为**模型 provider**，运行时仍是 OpenCode——不影响上表的职责划分。

## 远程访问的三条链路

| 方式 | 机制 | 适用 |
|------|------|------|
| **局域网直连** | 设备与实例同一 Wi-Fi，直连 `http://<ip>:3000` | 家中 / 办公室 |
| **Private Relay** | 双方各自向 Relay 建立 outbound 连接，Relay 转发**端到端加密**流量 | 任意地点，零配置 |
| **隧道** | Cloudflare / Ngrok 等暴露公网 URL，配 UI 密码 | 无法配对的普通浏览器 |

设计要点：

- 实例**从不监听公网入站连接**；
- 直连可用时优先直连，不可用时回退 Relay；
- Relay 是「盲信使」——不持有密钥，无法读取代码、提示词或密码；
- 配对二维码一次性使用，每设备独立令牌，可随时撤销。

## 本地状态与敏感文件

| 路径 / 项 | 内容 | 注意 |
|-----------|------|------|
| `~/.config/openchamber/relay-identity.json` | 实例的 Relay 身份密钥 | 泄露即可被冒充；勿放入备份、dotfiles 仓库或 bug 报告 |
| 设备令牌 | 每台已配对设备的凭证 | 可在 Settings 中逐台撤销 |
| UI 密码 | 浏览器访问凭证（可换用环境变量） | 支持 Passkey 登录 |
| `policy.json` | 企业策略文件（见 [[07-部署与安全]]） | 所有安装形态读取同一路径 |

## 企业策略的注入点

`policy.json` 可强制开启 enterprise mode、锁定自有 Relay、限制网络访问、白名单扩展来源。其设计原则是：**文件优先级高于用户设置与环境变量**；文件损坏时保护仍然生效，不会静默失效。

## 架构层面的取舍

| 选择 | 收益 | 代价 |
|------|------|------|
| 绑定 OpenCode | 浅耦合、稳定 API、开源可审计 | 无法纳管 Claude Code / Codex 等其他运行时 |
| 服务端持有会话 | 跨设备、后台持续、目标循环 | 必须保持实例运行；运维责任在用户 |
| 无自带编辑器 | 可寄生四款 IDE，获客成本低 | 依赖宿主扩展生态 |
| 自建 Relay | 零配置远程、不暴露端口 | 依赖官方 Relay 基础设施（企业可自建） |
