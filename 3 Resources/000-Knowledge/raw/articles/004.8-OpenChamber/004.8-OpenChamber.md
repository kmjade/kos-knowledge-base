# 004.8 OpenChamber

> **OpenChamber 是一个基于 [[3 Resources/000-Knowledge/raw/articles/004.8-OpenCode/004.8-OpenCode|OpenCode]] 的开源「智能体开发环境」（ADE）**：不提供编辑器，而是把 agent 会话的目标、并行运行、变更审阅、跨设备接续与远程访问组织成一套工作台。桌面端内置 OpenCode CLI，亦可作为 Web/PWA、VS Code 扩展、iOS/Android 客户端或自托管服务运行。MIT 许可。
>
> 用户原话概括其主张：**Run agent work. Keep control. Ship from anywhere.**

## 它在抽象栈里的位置

```
编辑器层      VS Code / Cursor / Windsurf / Trae
                ↑（VS Code 扩展可选嵌入）
工作台层      OpenChamber  ← 会话 · 目标 · 审阅 · 调度 · 跨设备
                ↑
运行时层      OpenCode CLI（唯一后端）
                ↑
模型层        Anthropic / OpenAI / Google / 本地模型（经 OpenCode 配置）
```

| 层 | 代表产品 | 解决的问题 |
|----|---------|-----------|
| 编辑器 | Windsurf→Devin Desktop、Trae、Cursor | 人在哪里写代码 |
| **工作台** | **OpenChamber**、Devin Desktop 的 Agent Command Center | agent 会话如何被管理、审阅、接续 |
| 运行时 | OpenCode、Claude Code、Codex CLI | agent 如何执行工具调用与文件修改 |
| 模型 | Claude / GPT / Gemini / 本地模型 | 推理能力从哪来 |

> 关键判断：OpenChamber 不与 IDE 竞争，而是**接管 agent 会话的生命周期**——这恰好是编辑器厂商最难做好的部分，因为编辑器的模型是「打开一个文件」，而非「维护一个持续运行的任务」。

## 实例模型：一台机器跑，任何设备接

官方中文站把它描述为**实例（instance）**架构：

| 层 | 行为 |
|----|------|
| **实例** | 运行在你掌控的 Mac / Linux 机器或自有服务器上；保留每一个会话，关闭应用后仍在 |
| **桌面应用** | 自身运行一个本地实例，**同时可连接远程实例**，在应用内直接切换 |
| **手机 / 浏览器** | 通过 Private Relay 访问任意一个实例；无需公网端口 |

配对链路由 CLI 生成：

```bash
openchamber connect-url --relay
# pairing link: openchamber://connect?v=2&p=…
# Server URL: http://192.168.1.24:3000
# Relay fallback: wss://relay.openchamber.dev/ws
# Fingerprint: C5E0-23FC
```

这解释了它为何能「换设备继续」：**会话状态属于实例，不属于客户端**。默认仅监听 localhost，加参数才向局域网开放。

## 核心能力

| 能力 | 机制 | 工程意义 |
|------|------|---------|
| **Session Goals** | 每轮结束后检查结果，未达标则继续，直到完成 / 受阻 / 触达上限；关闭应用后仍可继续 | 把「一问一答」升级为**带终止条件的自主循环** |
| **Multi-run** | 同一任务分给最多 **5 个模型**，各自独立 session，可选独立 worktree | 用并行采样替代「押注单一最强模型」 |
| **Fusion** | 将多个 run 中最强的部分合并为一个新 session | 从「择优」走向「合成」 |
| **Changes Walkthrough** | 把大 diff 拆成有顺序、有解释的步骤 | 解决 agent 产出「量大到人审不动」的瓶颈 |
| **Preview / Browser Use** | 在对话旁运行应用；你点击元素，agent 也能点击；agent 能看到报错并检查自己的工作 | 把模糊指代转成结构化上下文，并让 agent 自检 |
| **GitHub / Linear 工作流** | 从 GitHub issue / PR 或 Linear 工单启动会话，附带讨论串与 diff；失败 CI 回传 agent；可直接提交、推送、开 PR、回复评审、合并 | 把 agent 接入现有协作流程；GitLab 正在开发中 |
| **跨设备接续** | Desktop / Web / PWA / VS Code / iOS / Android 共享项目与会话，可重连运行中的终端 | 会话不再绑定单机 |
| **Private Relay** | 一次性二维码配对，端到端加密，可随时撤销；无需开放端口 | 远程访问不牺牲网络边界 |
| **调度** | 一次性 / 每日 / 每周 / cron；可叠加 Session Goals | 让 agent 从「被动响应」变为「按计划推进」 |
| **跨项目追踪** | 会话状态（工作中 / 等待 / 完成 / 失败）、审批、provider 限额、token 与成本 | 把 agent 当作可运营资源计量 |

## 多端矩阵

| 端 | 角色 |
|----|------|
| **Desktop**（macOS / Windows / Linux） | 完整工作台；多窗口、Mini Chat、远程机器、SSH、原生通知；**内置 OpenCode CLI** |
| **Web / PWA** | 浏览器打开、可安装为应用、后台通知 |
| **VS Code / Cursor / Windsurf / Trae** | 官方提供四款编辑器的扩展：会话置于代码旁；把选区发给 agent；结果回编辑器；对比并行 run |
| **iOS / Android** | 原生应用（目前 **beta**）与 PWA；离开桌面后审阅与指挥；完成提醒；触屏终端 |
| **CLI / Server** | 工作站或服务器常驻；调度、远程访问、登录后保持可用 |

## 安装与部署

| 方式 | 要求 |
|------|------|
| Desktop | 从 GitHub Releases 下载；已捆绑匹配版本 OpenCode CLI，无需另装 |
| Linux | `.deb`（Debian/Ubuntu）、`.rpm`（Fedora/openSUSE）、AppImage（需 FUSE，或用 `APPIMAGE_EXTRACT_AND_RUN=1`） |
| VS Code | Marketplace 搜索 "OpenChamber" |
| CLI / Web / PWA | **Node.js 24.14+**，并使用已安装的 OpenCode CLI；`curl -fsSL .../install.sh \| bash` 后 `openchamber --ui-password ...` |

常用命令：`openchamber status` · `connect-url --qr` · `tunnel start --provider cloudflare` · `startup enable` · `logs` · `stop` · `update`。

**费用与前置条件（官方 FAQ）**：OpenChamber 本身免费，只需自备模型服务商的密钥与额度；运行它需要一台装好 **OpenCode** 的机器（基于 OpenCode SDK）。

> ⚠️ 表述差异：README 称 Desktop 版**已捆绑匹配版本的 OpenCode CLI**，中文站 FAQ 仍写「装好 OpenCode 的机器」。二者可能对应不同版本或不同安装方式，实际以安装包行为为准。

## 隐私与数据（官方声明）

| 声明 | 内容 |
|------|------|
| 数据留存 | 代码与会话内容留在你的机器；**不收集**项目名、路径、提示词、代码、diff 或会话内容 |
| 本地实例 | 默认只监听 localhost |
| 远程访问 | UI 密码把守浏览器访问；隧道链接可轮换或撤销 |
| Private Relay | 一次性二维码配对；E2E 加密；不开放端口、不暴露公网；可随时撤销 |
| 可验证性 | MIT 开源，隐私模型可自行审阅代码核对 |

> 这些是**厂商声明**，不是第三方审计结论。

## 安全边界

- 默认绑定 **localhost**；
- `--lan` **仅在可信网络**使用；
- 浏览器访问必须设置 `--ui-password`；
- Private Relay 为 E2E 加密且可撤销；亦支持直连、LAN/VPN、Cloudflare/Ngrok、SSH；
- **开源 ≠ 默认安全**：Web/PWA + 远程访问 + 终端控制意味着攻击面不小，生产使用应置于内网或 VPN 之后。

## 与同类产品的路线对比

| 维度 | **OpenChamber** | Windsurf → Devin Desktop | Trae |
|------|-----------------|--------------------------|------|
| 本质 | 开源工作台（ADE） | 商业 IDE + 云代理 | 商业 IDE + SOLO |
| 自带编辑器 | 否（VS Code / Cursor / Windsurf / Trae 扩展 + 内置浏览器） | 是 | 是 |
| agent 运行时 | **OpenCode（唯一）** | 自有 Devin Local/Cloud | 自有 SOLO |
| 多代理策略 | 同任务多模型并行 + Fusion | **ACP 纳管第三方代理** | 自有 agent + 自定义 |
| 部署 | 桌面 / Web / PWA / VS Code / 移动端 / 自托管 | 桌面 + 云 | 桌面 + Web + 企业 |
| 许可 | **MIT** | 闭源 | 闭源 |
| 核心叙事 | 掌控 agent 工作流 | 代理指挥中心 | 从想法到上线 |

**路线差异一句话**：Windsurf 做「多代理宿主」，Trae 做「产品工厂」，OpenChamber 做「**可自托管的会话控制面**」。

## 边界与待核实

1. **运行时绑定**：只驱动 OpenCode，无法像 ACP 宿主那样接入 Claude Agent / Codex CLI；若工作流已押注 Claude Code，需评估迁移成本。
2. **独立性**：官方声明为独立项目，与 OpenCode 团队无隶属关系。
3. **成熟度**：建库约 13 个月，迭代活跃但 issue 存量 248，生产采用需评估稳定性。
4. **安全审计**：未见第三方安全审计公开报告；自托管场景需自行评估。
5. **「工作台层」是否成为独立品类**：目前仅少数产品明确以此定位，尚待市场验证。
6. **寄生式扩展的张力**：官方为 VS Code、Cursor、Windsurf、Trae 同时提供扩展——它选择嵌入竞争对手的 IDE，而非另造编辑器。这既降低获客成本，也使其命运部分取决于这些宿主是否继续开放扩展生态。
7. **集成覆盖**：GitHub、Linear 已支持，GitLab 标注「正在开发中」；移动端为 beta。
8. **文档一致性**：README 与中文站 FAQ 在「是否需自行安装 OpenCode」上表述不一致，落地前需以实际安装包验证。
