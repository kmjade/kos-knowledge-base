# 08 生态与扩展

OpenChamber 的扩展面有六层，容易混淆。先给一张分工表：

| 层 | 解决什么 | 配置位置 | 是否改变 agent 运行时 |
|----|---------|---------|---------------------|
| **Providers / Agents** | 模型从哪来、agent 的人格与工具权限 | Settings → Providers / Agents | 否（写入 OpenCode 配置） |
| **MCP Servers** | 给 agent 增加外部工具 | Settings → MCP | 否（OpenCode 加载） |
| **Skills** | 可复用的操作知识与流程 | Settings → Skills | 否 |
| **Extensions** | 在右栏加第三方面板，可读写文件、发消息 | Settings → Extensions | 否（OpenChamber 自身扩展） |
| **Integrations** | 一键接入 150+ 服务（含 MCP / 插件 / Skills） | Settings → Integrations | 间接 |
| **Project Actions** | 保存并一键运行项目命令 | Settings → Projects | 否 |

> 关键区分：**Extensions ≠ OpenCode plugins**。前者是 OpenChamber 的 UI 扩展，后者运行在 OpenCode 内部。

## Providers、Models 与 Agents

### 接入 provider

- **API Key**：粘贴密钥；
- **设备流登录**：显示链接 + 短码，浏览器授权后自动完成；
- **Custom / Other**：OpenAI 兼容端点（网关、校园 LLM、Ollama、LiteLLM 等），需填 provider ID、名称、base URL、API Key（或 `{env:VAR}`）、至少一个 model id，可选推理等级与请求头。

写入行为：provider 块写入 **OpenCode 配置**，密钥存入 **OpenCode auth**；因此与 OpenCode CLI 共享登录状态。项目级设置覆盖个人级设置。

### Agent

Agent 是一个命名配置：**模型 + 人格 + 权限**。

| 字段 | 作用 |
|------|------|
| description | 用途说明 |
| model | 默认模型 |
| temperature | 创造性 |
| prompt | 常驻指令 |
| tool rules | 允许使用哪些工具 |

## MCP Servers

| 类型 | 运行方式 | 配置 |
|------|---------|------|
| **local** | 在本机执行命令 | 命令 + 可选环境变量 |
| **remote** | 连接他人托管的 URL | URL + 可选请求头（如认证 token） |

作用域：

- **personal**：所有项目可用；
- **project**：仅当前项目，随项目设置保存。

服务名只允许小写字母、数字、连字符与下划线；保存后默认启用，可关闭而不删除。

## Skills

### 安装现成技能

**Settings → Skills → Catalog**：

1. 浏览内置源（如 Anthropic skills 仓库）或搜索；
2. 选择技能并安装；
3. 选择作用域：全局或当前项目；
4. 同名冲突时逐项选择跳过 / 覆盖。

### 添加自定义源

任何 Git 仓库都可作为源：`owner/repo` 或完整 URL；私有仓库需本机已配置 SSH key 或凭据。可指定分支 / 标签：`owner/repo#develop`、`https://github.com/owner/repo.git#v1.0.0`。

> 企业模式下可隐藏内置 skills 目录（`hideBuiltinSkillCatalogs`），只保留组织自建源。

## Extensions

### 安装方式

在 **Settings → Extensions** 的输入框中填入以下任一项：

- 本机文件夹绝对路径；
- `.zip` 文件路径；
- Git 仓库或 zip 的 https 链接；
- SSH Git 地址（`git@github.com:owner/extension.git`）。

可拖入 zip 或文件夹；远程实例也支持（上传到服务端）。文件夹安装直接运行原目录，便于开发调试；zip / URL 会复制到 OpenChamber 数据目录。

### 权限模型

显示面板、读取当前项目与会话 **无需授权**；以下行为需要一次性批准：

| 权限 | 含义 / 风险 |
|------|-------------|
| 发送消息 | 可写并发送提示词，消耗 token，可能触发工具 |
| 访问项目与会话 | 列出项目、worktree、会话状态；创建并打开会话（不暴露对话内容） |
| 读写项目文件 | 项目内任意文件 |
| 读写项目外文件 | 仅限对话框中列出的位置 |
| 使用 Small Model | 会话外的一次性生成，消耗 token |
| 连接外部服务 | 使用 Settings → Integrations 中连接的账号 |
| 读取会话对话 | 仅当你在该会话上执行扩展动作时 |
| 运行本地服务 | 以你的完整用户权限运行独立程序，**仅信任作者时允许** |

版本升级若申请更多权限，卡片显示 **Needs approval**，未批准前扩展保持关闭。

### 能力边界与限制

- 可提供全屏页面（如任务看板），需从 **Extension pages** 打开；
- 可在消息菜单、会话菜单、`+` 菜单、斜杠命令中添加入口；
- 可保存自己的数据到服务端，移除扩展时删除；
- 可提供「实时画面」并接管控制（如浏览器/模拟器），状态行显示 **You have control**，交还前 agent 的操作被拒绝；
- **VS Code 扩展与移动端不加载 Extensions**；
- 从 git URL 安装的扩展可自更新（每小时最多检查一次），文件夹 / zip 安装需手动替换。

## Integrations 目录

**Settings → Integrations** 提供 **150+ 服务**的一键接入：Linear、Notion、Sentry、Supabase、Figma、可观测性工具、CRM、会议纪要等。

安装通常做三件事之一：

| 产物 | 说明 |
|------|------|
| **MCP server** | agent 读写该服务的连接 |
| **Skills / Plugin** | 随服务附带；插件运行在 OpenCode 内，安装前显示许可证并需确认 |
| **本地服务** | 运行在 OpenCode 所在机器，可能需要 Node.js、Python + uv 或 Docker |

安装为用户级，所有项目可用；卸载只移除目录添加的内容，服务账号不受影响。**企业模式下整个目录被隐藏。**

### GitHub 与 Linear

| 平台 | 能力 |
|------|------|
| GitHub | 从 issue/PR 启动会话、附加上下文、创建/更新/合并 PR |
| Linear | 多工作区切换、按团队/状态/负责人/优先级筛选、从 issue 启动 worktree 会话、附加到消息、可选的会话评论回写 |

### Claude Code 集成（重要辨析）

OpenChamber 提供 **Claude Code 集成**：通过 Anthropic 官方 **Claude Agent SDK** 与你本机已安装的 **Claude Code CLI**，使用 Claude Pro / Max 订阅额度，无需 API Key。官方强调其走 Anthropic 支持的访问路径，不做 OAuth 劫持或 token 重放。

> 但这不等于「OpenChamber 能纳管 Claude Code 作为 agent 运行时」：
> - **能**：把 Claude 订阅接入为 OpenCode 的模型 provider；
> - **不能**：让 Claude Code 自带的工具链、Skills、Hooks 取代 OpenCode 执行。
>
> 运行时仍是 OpenCode，Claude Code 在这里是**模型接入通道**。

## Project Actions

把常用命令保存为一键动作（dev server、build、test）：

| 项 | 说明 |
|----|------|
| 配置 | Settings → Projects → Project Actions；可限定操作系统 |
| 运行 | Work Status 面板的动作行；快捷键 `⌘⌥R` / `Ctrl+Alt+R`；命令面板搜 "run" |
| 执行位置 | 会话所在文件夹；worktree 会话中即 worktree |
| 自动打开 | 开启 **auto-open URL** 后监听输出中的本地地址；也可填固定 URL |
| 占位符 | `{worktree}`、`{branch}`，使同一动作适配所有 worktree |
| 平台 | 桌面与 Web；VS Code、手机、Chats 下不可用 |

## 定时任务与 Loops

### UI 定时任务

支持 **daily / weekly / once / cron**；可指定 prompt（也可是斜杠命令）、provider、model、agent；可勾选 **Run as goal**；支持 **run now** 试跑。

### Loops：以 Markdown 定义

将文件放入 `.agents/loops/`（项目级，可位于项目目录至 worktree 根之间的任意祖先目录）或 `~/.agents/loops/`（用户级），在 Scheduled Tasks 中同步，无需重启。

```markdown
---
name: daily-digest
schedule: "0 9 * * *"
enabled: true
model: anthropic/claude-sonnet-4-5
agent: plan
timezone: Europe/Kyiv
---
Summarize repository changes since yesterday and post the digest.
```

| 规则 | 说明 |
|------|------|
| 文件权威 | 文件存在时以文件为准；删除任务会删除文件（需确认） |
| 默认关闭 | 提交文件不会自动运行；仓库带来的 loop 也需手动开启 |
| 运行状态 | 上次/下次运行等写入项目配置，**不回写** Markdown |
| 解析失败 | 保留最后一次有效定义，直到文件修复 |
| 调度类型 | loop 仅支持 cron；daily/weekly/once 仍为 UI 专属 |
| 前提 | **服务端必须运行**，否则任务暂停 |

## Agent Control Tool

OpenChamber 提供一个内置 `openchamber` agent 工具，让 agent 在对话中管理应用本身：

| 能做 | 不能做 |
|------|--------|
| 列出项目与模型偏好 | 删除会话或 worktree |
| 创建会话、追问、fork | 注册项目路径 |
| 创建隔离 worktree 会话 | 运行任意 shell 命令 |
| 管理定时任务（创建 / 立即运行） | 调用任意 URL |
| 查询指定会话的最新回复 | — |

默认在 OpenChamber 自管 OpenCode server 时启用；连接外部 OpenCode server 或运行于 VS Code 扩展时不可用。可在 **Settings → General → OpenChamber Tools** 关闭，下一轮生效。

> 意义：这把「工作台」变成了 agent 可调用的 API——agent 不只写代码，还能**为自己派生新会话**。

## 企业模式下的收缩

| 被关闭 | 备注 |
|--------|------|
| 在应用内接入模型 provider | 最终闸门在 OpenCode 策略 |
| 分类 provider / 自动判断 | 可用策略固定自有端点 |
| 外部隧道 | 边缘解密，风险高 |
| Integrations 目录 | 整个隐藏 |
| 可外发数据的扩展 | 除非在 `allowedExtensions` 白名单 |
| 推送通知正文 | 仅通用标题 |
| 网络监听 | 需显式 `allowNetworkAccess` |
