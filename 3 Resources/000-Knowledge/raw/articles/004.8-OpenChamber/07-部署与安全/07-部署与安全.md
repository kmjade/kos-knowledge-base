# 07 部署与安全

## 部署形态

| 形态 | 运行位置 | 适用 |
|------|---------|------|
| Desktop | 本机；也可连接远程实例 | 个人日常 |
| CLI / Server | Mac / Linux / 服务器常驻 | 自托管、多设备 |
| Docker | 容器；需允许网络访问 | 团队服务器 |
| VS Code 扩展 | 编辑器进程内 | 代码旁使用 |

核心原则：**实例跑在你掌控的机器上**，客户端只是视图。

## 网络暴露的三个层级

| 层级 | 配置 | 风险 |
|------|------|------|
| 仅本机 | 默认 `127.0.0.1` | 最低 |
| 局域网 | `--lan` 或 `--host` | 同网段可访问；HTTP 明文 |
| 公网 | 隧道（Cloudflare/Ngrok）或反向代理 + HTTPS | 最高；必须强密码 |

> 官方建议：自有设备优先用**配对 + Private Relay**，完全不对公网暴露；确需公网 URL 时优先隧道或 VPN，而非直接开端口。

## 认证体系

| 机制 | 说明 |
|------|------|
| **UI 密码** | `--ui-password <pwd>` 或环境变量 `OPENCHAMBER_UI_PASSWORD`；登录后设备会被记住一段时间 |
| **Passkey** | 密码设置后可在 Settings → OpenChamber → Passkeys 添加 Face ID / Touch ID / 安全密钥；**更换或移除密码会清空已存 Passkey** |
| **设备令牌** | 配对设备使用各自令牌，**不暴露 UI 密码**；每台设备独立、可单独撤销 |
| **配对链接** | 一次性使用，未使用会过期 |

## Private Relay

### 工作方式

```
你的实例 ──outbound──► Relay ◄──outbound── 你的设备
             （端到端加密，Relay 无密钥）
```

- 实例主动向 Relay 建立并保持**出站**连接；
- 设备在外网时也连接 Relay，由 Relay 转发**密封流量**；
- **本机不监听任何来自互联网的入站连接**；
- 回到同一 Wi-Fi 时优先直连，跳过 Relay。

### Relay 能看到什么

| 能 | 不能 |
|----|------|
| 转发加密流量 | 读取代码、提示词、密码 |
| 维护连接状态 | 发现未配对的实例 |
| — | 绕过一次性配对令牌接入 |

### 生命周期

- 创建 **Anywhere** 配对时自动开启；
- 只要仍有设备依赖就持续存在，重启后恢复；
- 最后一个 Relay 设备被撤销后自动关闭；
- Settings → Remote Instances → OpenChamber Relay 可查看状态并 **Disable**（局域网设备不受影响）。

### 敏感文件

`~/.config/openchamber/relay-identity.json` 保存实例的 Relay 身份密钥：

- 仅当前用户可读；
- **泄露即可被冒充**；
- 不得进入 bug 报告、共享备份或 dotfiles 仓库。

### 自建 Relay

企业可部署 [openchamber-relay](https://github.com/openchamber/openchamber-relay)，通过 `relayUrl` 或 `OPENCHAMBER_RELAY_URL` 指向自有地址。官方 Relay 本身也无法读取流量（E2E），自建的价值在于**把连接元数据与入口留在自己网络内**。

## 隧道 vs Relay

| | Relay | 隧道 |
|--|-------|------|
| 面向 | 你自己的已配对设备 | 任意普通浏览器 |
| 暴露 | 不暴露公网 | 生成公网 URL |
| 认证 | 设备令牌 | UI 密码 |
| 前提 | 需配对 | 无需配对 |
| 风险 | 低 | 隧道提供商在边缘解密，可见明文请求 |

## 企业模式（Enterprise Mode）

### 启用方式

| 方式 | 适用 | 强度 |
|------|------|------|
| `policy.json` | 受管笔记本、服务器 | 强（用户不可覆盖） |
| `OPENCHAMBER_ENTERPRISE_MODE=1` | 服务器 / 容器 | 中（笔记本上用户可改 shell 配置） |

### 策略文件路径

| 系统 | 路径 |
|------|------|
| macOS | `/Library/Application Support/OpenChamber/policy.json` |
| Windows | `C:\ProgramData\OpenChamber\policy.json` |
| Linux | `/etc/openchamber/policy.json` |

所有安装形态（桌面、npm Web、CLI、VS Code 扩展）读取**同一文件**；Docker 挂载到 Linux 路径。

### 关键字段

| 字段 | 作用 |
|------|------|
| `enterpriseMode` | 唯一必需项 |
| `organization` | Settings 显示 "Managed by …" |
| `relayUrl` | 锁定自有 Relay |
| `jev` | 锁定自有分类/审计端点 |
| `allowNetworkAccess` | 是否允许其他设备访问 |
| `allowedExtensions` | 可信扩展仓库白名单（以 `/` 结尾可覆盖其下全部仓库） |
| `opencodeBinary` | 固定 OpenCode CLI 路径 |
| `hideBuiltinSkillCatalogs` | 隐藏内置 skills 目录 |

### 优先级与失效行为

- **文件 > 用户设置 > 环境变量**；
- 文件存在但损坏/不可读时，**企业模式仍然开启**，只是不锁定具体项——不会静默失效；
- 变更无需重启；
- 注意：OpenChamber 以当前用户身份运行，**用户可读取该文件**，因此不要把 API Key 写进去。

### 企业模式下被关闭的能力

- 在 OpenChamber 内连接/登录模型 provider、添加密钥、创建自定义 provider；
- 分类 provider（Jev）与自动判断；
- OpenAI 朗读；
- 外部隧道（Cloudflare / ngrok）；
- 公网 CDN 字体回退到系统字体；
- 共享 Relay（必须自建）；
- 可外发数据的扩展，除非在 `allowedExtensions` 中；
- 推送通知仅含通用标题，不含消息正文或会话名；
- 网络监听默认关闭，`--lan` 也会被拒绝（需显式 `allowNetworkAccess`）。

> 模型 provider 的最终闸门在 **OpenCode 策略**，而非 OpenChamber。官方示例：先 deny 全部 provider，再 allow 白名单。

## 固定 OpenCode CLI

```json
{
  "opencodeBinary": "/usr/local/bin/opencode"
}
```

- 只从该路径启动 OpenCode，忽略 Settings、`OPENCODE_BINARY` 与桌面版捆绑副本；
- 路径不可执行时**不回退**，直接报错并指出路径；
- 需要 **OpenCode 2.x** 且不低于 OpenChamber 要求的版本；
- 可通过目录指定（目录内需有 `opencode` / `opencode.exe`）；
- OpenChamber **不负责安装或升级**被固定的 OpenCode。

## 部署检查清单

- [ ] 已设置强 UI 密码（或确认仅 localhost 访问）
- [ ] 未使用 `--lan` 时，确认无需局域网访问
- [ ] 公网暴露前已启用 HTTPS / 反向代理
- [ ] 已配对设备列表逐台核对，撤销不用的设备
- [ ] `relay-identity.json` 未被纳入备份或版本控制
- [ ] 企业环境已部署 `policy.json` 并验证 Settings 显示组织名
- [ ] 已用 OpenCode 策略限制可用的模型 provider
- [ ] 需要审计时，确认 Jev / 分类端点指向自有基础设施
