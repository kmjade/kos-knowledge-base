# 04 会话与目标

## 什么是 Session Goal

Session Goal 把一次提示词变成一条**终点线**：设定目标后，OpenChamber 在每一轮结束后自动检查进度，未完成就继续推进，直到目标达成、被判定受阻，或触达安全上限。

它解决的是 agent 工作流里最常见的摩擦：**人成了「继续」按钮**。

> 与「多轮对话」的区别：会话是一次交互，目标是**带审计与终止条件的持久循环**。

## 启动目标的四种方式

| 入口 | 操作 |
|------|------|
| 新会话 / 现有会话 | 点 composer 上的目标按钮（亮起即武装）→ 输入并发送，首条消息成为目标 |
| 从 agent 回复派生 | 在「Start new session from this answer」中勾选 **Run as goal**；可叠加 **Create worktree** |
| 从已保存计划 | 在新会话或 worktree 中实施计划时勾选 **Run as goal**，计划内容成为目标 |
| 定时任务 | 在 scheduled task 上勾选 **Run as goal**，每次触发都追求完成 |

## 目标必须自包含

审计器**只能看到「目标 + agent 最新一轮回复」**，看不到聊天历史。因此目标要写成脱离上下文也能判断「完成没有」的句子。

| ✅ 好目标 | ❌ 坏目标 |
|----------|----------|
| 「为 export 模块补充测试，并让整个测试套件通过。」 | 「修一下。」 |
| 「把 README 的安装步骤改为三条路径，并确保命令可复制执行。」 | 「继续刚才那个想法。」 |

> 小范围追问不需要目标，直接发普通消息即可。

## 循环机制

```
agent 停止 → 会话静默片刻
        ↓
廉价小模型审计：继续 / 完成 / 受阻？
        ↓
继续 → 发送续跑提示 → agent 接着做
完成 → 目标结束 + 通知
受阻 → 连续三次审计都判受阻才停下（避免偶发卡顿误杀）
```

### 安全上限

| 机制 | 作用 |
|------|------|
| **Token 预算** | 可在目标对话框或 Settings → Chat → Goal 设置；触达即停，可追加后恢复 |
| **续跑次数上限** | 防止无限循环 |
| **轮次错误停止** | 本轮出错即停，不盲目重试 |
| **上下文压缩后继续** | 撞到上下文窗口被视为「工作未完成」的证据，循环继续 |

## 停止、暂停与恢复

| 操作 | 行为 |
|------|------|
| **停止按钮** | 中止当前轮并暂停目标；显式停止优先于循环 |
| **暂停** | 与停止等效，从目标条触发 |
| 暂停期间 | 可正常对话，循环不干预 |
| **恢复** | 空闲会话立即发出续跑提示；agent 正在工作时，等其下次暂停再静默接回 |

## 状态与可见性

- 目标条显示：最新进度说明、状态、token 用量、暂停/恢复按钮；
- agent 停止且目标活跃时显示 **Evaluating…**（静默窗口 + 审计进行中）；
- 目标按钮颜色：运行中蓝、完成绿、受阻或超预算红；
- 会话侧边栏日期旁的小目标图标反映状态；
- 一个会话同一时间只能有一个目标；已完成目标只读，需移除后再设新目标。

## 通知策略

| 场景 | 行为 |
|------|------|
| 目标运行中 | **抑制**每轮的「agent 已就绪」通知，避免与续跑循环重复 |
| 目标结束（完成 / 受阻 / 超预算） | 发送**一条**最终通知，桌面 + 移动推送 |
| 权限请求、提问、错误 | 始终正常通知 |

## 运行位置与计费

- 循环运行在 **OpenChamber 服务端**，不在浏览器标签里——关标签、锁手机都不影响；
- 前提是实例进程（桌面应用或 `openchamber` 进程）保持运行；
- 目标使用会话自身的 provider 与模型，**审计调用也走同一 provider**，不向第三方外发；
- 审计调用建议使用便宜的小模型以控制成本。

## 实践建议

1. **目标写结果，不写步骤**——审计器判断的是终态。
2. **配套预算**——长任务先设 token 上限，避免无人值守时烧额度。
3. **配合 worktree**——有风险的自主执行放进隔离分支。
4. **配合定时任务**——把「每天跑一次检查并修到通过」变成常规操作。
5. **受阻不等于失败**——需要人决策时它会主动停下，这比硬撑更可靠。
