# PARA 方法概览

> **资源：** 由 Tiago Forte 提出的个人知识管理方法论。
> UDC: 001.8:005（知识组织与管理方法）

---

## 核心内容

### 什么是 PARA？

PARA 是四个顶级文件夹的首字母缩写：

| 层级 | 名称 | 说明 | 特征 |
|------|------|------|------|
| **P** | Projects（项目）| 有截止日期的目标 | 短周期、可完成 |
| **A** | Areas（领域）| 持续关注的责任范围 | 长期、无截止日 |
| **R** | Resources（资源）| 未来可能用到的主题资料 | 持续积累、按主题 |
| **A** | Archives（归档）| 已完成或暂不活跃的内容 | 冷存储、可恢复 |

### 核心原则

1. **项目驱动** — 只有项目才有截止日期，领域和资源没有
2. **当前优先** — 只保留当前需要的项目，其余归档
3. **按需展开** — 不预先分类，需要时再建立结构
4. **定期清理** — 每周/每月回顾，归档已完成项目

### PARA 的信息流

```
采集 → 项目化 → 执行 → 完成 → 归档
           ↓
         未启动则存入资源
```


### PARA vs GTD

| 维度 | PARA | GTD（Getting Things Done） |
|------|------|---------------------------|
| 焦点 | 知识组织 | 任务清零 |
| 存储 | 按生命周期归档 | 按上下文归类 |
| 回顾 | 每周/月回顾 | 每周回顾 |
| 最大区别 | 项目完成后知识可复用 | 项目完成后即归档 |

PARA 与 GTD 可以共存：GTD 处理"今天做什么"，PARA 处理"知识如何积累"。
### 在本系统中的实现

KOS_LLM-Wiki 使用以下文件夹结构对应 PARA：

| PARA 层 | 本系统目录 | 说明 |
|---------|-----------|------|
| P | `1 Projects/` | 每个项目一个子目录 |
| A | `2 Areas/` | 持续关注的领域 |
| R | `3 Resources/` | 000-Knowledge 子库 |
| A | `4 Archives/` | 已完成的项目 |
