# 06 记忆与上下文

## 持久记忆

Hermes Agent 拥有**有界且经过筛选**的持久记忆，跨会话保留偏好、项目与环境知识。由两个文件组成：

| 文件 | 用途 | 字符限制 |
|------|------|----------|
| `MEMORY.md` | Agent 的个人笔记（环境事实、约定、经验） | 2,200 字符（约 800 token） |
| `USER.md` | 用户档案（偏好、沟通风格、期望） | 1,375 字符（约 500 token） |

两者存于 `~/.hermes/memories/`，会话开始时作为**冻结快照**注入系统提示（保护前缀缓存）。Agent 通过 `memory` 工具自行管理：`add` / `replace` / `remove`（后两者用子字符串匹配）。

### 应保存 vs 忽略

| 应主动保存 | 应忽略 |
|-----------|--------|
| 用户偏好、环境事实、修正信息 | 琐碎/显而易见的信息 |
| 项目约定、已完成的工作 | 易重新发现的常识 |
| 明确请求 | 原始数据转储、会话特有一次性信息 |

记忆满时（超 80%），Agent 应合并/替换旧条目腾出空间。

## 会话搜索

`session_search` 工具搜索过往对话——所有 CLI/消息会话存于 SQLite（`~/.hermes/state.db`）+ FTS5 全文索引，查询结果由 Gemini Flash 摘要。

| 特性 | 持久记忆 | 会话搜索 |
|------|----------|----------|
| 容量 | 约 1,300 token | 无限制 |
| 速度 | 即时（在系统提示中） | 搜索 + LLM 摘要 |
| 用途 | 始终在上下文的关键事实 | 查找特定过往对话 |

## 外部记忆提供者

内置记忆之外，可接入 8 个外部提供者插件：Honcho、OpenViking、Mem0、Hindsight、Holographic、RetainDB、ByteRover、Supermemory——提供知识图谱、语义搜索、自动事实提取，与内置记忆**并行**运行。

## 上下文文件

Hermes 自动发现并加载项目上下文文件：

| 文件 | 用途 | 作用域 |
|------|------|--------|
| `SOUL.md` | 主 Agent 身份（系统提示第 #1 槽） | `~/.hermes/SOUL.md` |
| `.hermes.md` / `HERMES.md` | 项目特定指令（最高优先级） | 向上遍历至 Git 根 |
| `AGENTS.md` | 项目编码规范 | 递归目录遍历（可层级合并） |
| `CLAUDE.md` / `.cursorrules` | 兼容其他工具上下文 | 当前工作目录 |

项目上下文文件优先级：`.hermes.md` → `AGENTS.md` → `CLAUDE.md` → `.cursorrules`（首个匹配胜出）。

## 上下文引用与检查点

- **上下文引用**：输入 `@` + 文件/文件夹/git diff/URL，把内容内联注入消息
- **检查点与回滚**：修改文件前自动快照工作目录，`/rollback` 安全回滚（`checkpoints.max_snapshots` 可配）
- **上下文压缩**：接近上下文窗口阈值时，自动摘要中间轮次（`compression.threshold` 默认 0.50）
