# 06 组织和协会的专用复分

> **UDC `06.01/.05`** — 本页不是「一种组织」，而是**一个编号工具**：UDC 给 `06` 类配的**专用复分表**，用来在不新开主类号的前提下，给「组织」加一个**方面或属性**的限定。
> 归属判据一句话：**问「这个类号是怎么拼出来的、`.01`–`.05` 与 `061.x` 有何不同」，而不是「这个组织是什么类型」。**
> 所属：[[06-一般性质的组织|06 一般性质的组织]]（一般性质的组织）· 落位：`06-一般性质的组织/raw/articles/06-组织和协会的专用复分/`。
> ⚠️ **双重提醒**：① 本页序号 `06` 是**容器内序号**，恰好与 UDC `06` 同形，**不是类号**（见 [[_meta/architecture/adr/ADR-010-两级编号契约与DDC-UDC缝隙裁决规则|ADR-010]]）；② 复分号的逐条含义——**`06.01` = 会员的权利与义务** · **`06.05` = 奖励、荣誉、奖品、颁奖**（均经用户提供，见 [[06.01-会员的权利与义务|06.01 会员的权利与义务]] · [[06.05-奖励、荣誉、奖品、颁奖|06.05 奖励、荣誉、奖品、颁奖]]），**`06.02`–`06.04` 仍本页未核**，须以 UDCS 原文为准（见待补清单）。

## 二、UDC 复分体系三分

| 类型 | 写法 | 作用范围 | 例 |
|:--|:--|:--|:--|
| **通用复分**（common auxiliaries） | `+` `/` `:` `::` `=` `(1/9)` `(=…)` `"…"` `A/Z` | **全表通用** | `06:33` 组织的经济方面 · `06(510)` 中国的组织 |
| **专用复分**（special auxiliaries） | `.01/.09` · `-1/-9` · `'1/'9` · `.1/.9` | **仅限本类及其下位** | `06.01`–`06.05`（本页） |
| **类内细分**（主表下位） | `061` · `061.1` · `069` | 主表本身的层级 | `061.1` 政府组织 |

> ⚠️ **最容易混的一点**：`061.1` 里的 `.1` 是**主类号层级**的一部分（`061` 的下位），**不是**专用复分。专用复分区的标志是 `.01`–`.09`（**两位起、以 0 开头**）与 `-1/-9`、`'1/'9`。
> 📌 **判据口诀**：**`.01`–`.09` 是「加角度」，`061.x` 是「分子类」**。前者不改变「这是组织」这一归属，后者是主表替你列好的下位。

## 三、`06.01/.05` 的结构位置

| 项 | 现状 |
|:--|:--|
| 类号范围 | `06.01` – `06.05`（UDCS 将 `06` 的专用复分标为 `06.01/.05`） |
| 依附性 | 必须与主类号 `06` 连用，不能独立成一个类目 |
| 书写 | 主类号后紧接小数点与两位复分号，如 `06.01` |
| 逐条含义 | `06.01` = **会员的权利与义务**、`06.05` = **奖励、荣誉、奖品、颁奖**（均经用户提供，各建落位页 [[06.01-会员的权利与义务\|06.01 会员的权利与义务]] · [[06.05-奖励、荣誉、奖品、颁奖\|06.05 奖励、荣誉、奖品、颁奖]]，**待 UDCS 原文核验**）；`06.02`–`06.04` **未核** |
| 与 `061.1/.2` 的区别 | `061.1` 政府组织、`061.2` 非政府组织属**主表下位**；`.01`–`.05` 属**复分** |
| 是否存在 `-1/-9` 型复分 | 未核（若存在，则与本表并存，用法须分别说明） |
| 已建实例（组合号） | `06.05NOBEL:172.4` **诺贝尔和平奖**（`06.05` + A/Z **字母细分** `NOBEL` + `:172.4` **复合号**），落位页 [[06.05NOBEL：172.4-诺贝尔和平奖\|06.05NOBEL:172.4 诺贝尔和平奖]]（**容器直属子库**） |

> 📌 **复分号可以继续加挂字母与复合号**：`06.05` 是复分区的一个「面」（奖励 · 荣誉），字母细分再把面落到**具体对象**（`NOBEL`），冒号复合再挂**领域**（`:172.4`）。三层依次变窄，**顺序不可颠倒**：`06.05:172.4NOBEL` 会被读成「和平领域里的某个字母」，与 `06.05NOBEL:172.4` 完全不同。字母细分的实现方式各馆不一，`NOBEL` 与 `172.4` 的语义**均依用户给定、待核**。

> ⚠️ **不要凭类号外形推断含义**：`.01`–`.09` 在 UDC 中常被用作「观点 / 方面」复分，但**具体每一号的语义必须逐个核对**——同形号在不同类下的所指可以不同（专用复分的「专用」二字就是这个意思）。

## 四、使用规则（UDC 通则，框架级）

| 规则 | 内容 | 违反的后果 |
|:--|:--|:--|
| ① 从简 | 不用复分能表达清楚的，不必加复分 | 类号退化为句子，排架与检索双输 |
| ② 依附 | 复分必须挂在主类号之后，不可独立成号 | 得到不存在的类目 |
| ③ 顺序 | 主类号 → 专用复分 → 通用复分 | 顺序错乱即读成别的意思 |
| ④ 单一 | 同一复分表中通常只用一次 | 重复复分无检索价值 |
| ⑤ 不改归属 | 复分只收窄、不转移主类 | 把复分当主类，主题归属就错了 |
| ⑥ 逐级 | 复分本身可有层级（`.01` → `.011` 一类） | 越级引用失去可读性 |

> 📌 **实用取舍**：知识库自建时，**类号到 `06` / `061.x` 一级通常足够**。复分一旦用到 `.01`–`.05`，检索成本上升而聚类收益下降——除非语料在同一主题下确有稳定的「方面」分化。

## 五、四组易混对照

| 写法 | 实为 | 读法 |
|:--|:--|:--|
| `06.01` | `06` + **专用复分** `.01` | 会员的权利与义务（`06` 的一个**方面**） |
| `061` | **主表下位** | 组织及其他合作类型（落位页 [[061-组织及其他合作类型\|061 组织及其他合作类型]]） |
| `061.1` | 主表下位的**再下位** | 政府组织（**不是** `061` 的复分） |
| `06-05` | 若存在，为 `-0…` 型**专用复分** | 与 `06.05` 完全不同，不可混写 |

> ⚠️ **`.05` 与 `-05` 不可互换**：前者是 `.0x` 型复分，后者（如无）是 `-0x` 型；两者在 UDC 中属不同的复分表，混用即错号。

## 六、跨体系对照

| 体系 | 有无专用复分 | 处理方式 |
|:--|:--|:--|
| UDC | **有** | `.01/.09` · `-1/-9` · `'1/'9` · `.1/.9` |
| DDC（`060`） | 无同类机制 | 用**标准复分表**（T1–T6）与类表注记 |
| CLC（中图法） | 无 | 以类目层级 + 复分表（总论复分、专用复分表按类设置）另行处理 |

> 📌 **映射纪律**：UDC 的 `06.01` 在 DDC 中**没有等号对应**；跨体系映射须先**把类号还原成主题短语**，再在目标体系中重新归类——直接搬号是最常见的映射错误。

## 七、实践建议

| 场景 | 建议 |
|:--|:--|
| 建库初期 | 只到 `06` / `061.x`，不启用 `.01`–`.05` |
| 语料出现稳定「方面」分化 | 再引入复分，并在 schema 中登记所用复分号 |
| 与他库交换数据 | 复原主题短语再映射，不做号码直搬 |
| 复分语义未核前 | 标注「待核」，不写入检索键 |

## 八、核心问题

> 分类的复分机制，是在「**让类号说得更细**」与「**让类号还能被人读懂**」之间取平衡。角度加得越多，号码越像一句被压缩的话；而分类的价值恰恰在于**能被人正确读出**。**一个需要查三次复分表才能读懂的类号，在检索上的收益通常抵不过它在理解上的代价。**
